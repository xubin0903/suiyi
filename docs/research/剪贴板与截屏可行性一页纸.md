# 随译 · 剪贴板 + 截屏/裁剪翻译 · 跨端可行性一页纸

> 调研日：2026-09-20｜产品：「随译」开源翻译  
> 已拍板：随时复制译｜快捷键框选→OCR→译｜偶发长文走自研 Context Layer（不默认本地 LLM）｜引擎先 CT2/OPUS｜中文优先｜第一期倾向 Win 可演示｜非目标：IME / 视频字幕 / 读屏  

**决策摘要：** Windows 两条工作流均可工程落地，建议**立刻冻结 Win 为第一演示端**；Android 可行但商店/权限摩擦大；iOS「随时复制」与「全局框选截屏」均严重受限；鸿蒙三方应用剪贴板读取与系统截屏 API 门槛高，不宜作一期。

---

## 1. 两条工作流（时序）

### A. 复制译（Clipboard Translate）

```
用户在任意应用复制文本
    → OS 剪贴板变更
    → [随译] 监听/读取文本（端能力决定能否后台静默）
    → 短文：直送本地 NMT 服务（CT2/OPUS）
    → 长文/多句：先过 Context Layer（切分·术语·一致）再 NMT
    → 浮层/托盘窗呈现译文（可复制回剪贴板）
```

### B. 裁剪译（Region OCR Translate）

```
用户按全局快捷键 / 功能键
    → [随译] 全屏半透明遮罩，拖拽框选区域
    → 区域位图截取
    → OCR（开源或系统）→ 原文文本
    → 同 A：短文直译 / 长文 Context Layer → NMT
    → 结果窗呈现（原文 | 译文）
```

两条流**共用同一本地引擎服务**（见引擎验收标准 v0.1）。

## 2. 跨端可行性矩阵

| 能力 | Windows | Android | iOS | 鸿蒙 NEXT |
|------|---------|---------|-----|-----------|
| **剪贴板读取** | **可行**：`AddClipboardFormatListener` + `WM_CLIPBOARDUPDATE`，后台托盘可静默读文本。[文档](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-addclipboardformatlistener) | **受限**：Android 10+ 仅默认 IME / 有焦点 / 无障碍等可后台读；12+ 读剪贴板会 Toast；「随时复制译」难静默。[官方](https://developer.android.com/privacy-and-security/risks/secure-clipboard-handling) | **受限**：iOS 14+ 横幅；16+ 非用户意图读取弹授权；应用内粘贴/`UIPasteControl` 才顺滑，**无法可靠「复制即译」**。[UIPasteboard](https://developer.apple.com/documentation/uikit/uipasteboard) | **受限**：读内容需 `READ_PASTEBOARD`（审核/ACL 严）；推荐 `PasteButton` 用户点击临时授权，**非静默监听**。【已知+待验证上架细则】 |
| **全局快捷键** | **可行**：`RegisterHotKey`。[文档](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey) | **受限**：无真正系统级热键；靠悬浮球/`SYSTEM_ALERT_WINDOW` 或无障碍手势 | **难**：无第三方全局热键；仅 Shortcuts/Action Button 等迂回 | **受限/待验证**：桌面端可能有全局快捷键；手机端多依赖悬浮窗 |
| **区域截屏** | **可行**：遮罩框选 + GDI `BitBlt` 区域拷屏（经典路径，[Capturing an Image](https://learn.microsoft.com/en-us/windows/win32/gdi/capturing-an-image)）；或 `Windows.Graphics.Capture`（`CreateForMonitor` / Picker，[Screen capture](https://learn.microsoft.com/en-us/windows/apps/develop/media-authoring-processing/screen-capture)）再裁剪 | **可行但重交互**：每次需 `MediaProjection` 用户授权；悬浮层框选后裁剪帧；Android 14+ 可单应用共享、状态栏提示更醒目。[Media projection](https://developer.android.com/media/grow/media-projection) | **难（全局）**：第三方难做「任意他App 上框选」；ReplayKit 广播扩展可录屏但非轻量框选；ScreenCaptureKit 在新系统仍偏系统协作场景，**不能当作 Win 式一键裁剪**。【已知限制+OS 版本演进待跟】 | **难（三方）**：`@ohos.screenshot` / `CAPTURE_SCREEN` 文档标明**系统接口、仅系统应用**。【已知】社区 PC 笔记 demo 存在，上架路径【待验证】 |
| **OCR 候选** | 系统：`Windows.Media.Ocr`（随语言包，[OcrEngine](https://learn.microsoft.com/en-us/uwp/api/windows.media.ocr.ocrengine)）；开源：RapidOCR/ONNX PP-OCR、PaddleOCR、Tesseract | ML Kit Text Recognition / 自带 RapidOCR·Paddle；无障碍 `takeScreenshot` 另有政策风险 | **系统强**：Vision `VNRecognizeTextRequest` 端侧多语种。[文档](https://developer.apple.com/documentation/vision/recognizing-text-in-images) | Core Vision Kit `textRecognition.recognizeText`（官方 Codelab 存在） |
| **权限与商店风险** | 桌面分发自由度高；截屏黄边/能力声明需注意；杀软偶发误报【推测】 | Play：悬浮窗+录屏组合易触发审查；**禁止用无障碍「仅方便翻译」**（须真实无障碍用途） | 剪贴板隐私严格；全局截屏类能力极易拒审或根本做不到产品形态 | 剪贴板读权限与系统截屏对三方极严；华为上架审核【待验证】 |

**OCR 开源速览（中文优先）：**

| 方案 | 特点 | 一期建议 |
|------|------|----------|
| RapidOCR（ONNX PP-OCR） | 轻、可打包、中英强；文档见 [RapidOCR](https://rapidai.github.io/RapidOCRDocs/main/install_usage/rapidocr/install/) | **Win MVP 首选** |
| PaddleOCR | 效果上限高，部署偏重 | 质量对照基线 |
| Tesseract | 成熟，中文 UI/复杂排版弱于 PP-OCR 系 | 备选/西欧语 |
| Windows.Media.Ocr | 零模型体积，依赖语言包，中文效果参差 | 快速探针 / 降级 |
| 系统 OCR（Android ML Kit / iOS Vision / 鸿蒙 CoreVision） | 集成省事 | 各端优先考虑，Win 仍用 RapidOCR 保中文 |

## 3. 每端结论与 MVP 建议

| 端 | 总评 | MVP 建议 |
|----|------|----------|
| **Windows** | **可行** | **一期演示端**：托盘 + 复制监听 + 热键框选 + RapidOCR + 本地 CT2 服务 |
| **Android** | **受限** | 二期：悬浮球触发「粘贴译」+ MediaProjection 框选 OCR；不做静默剪贴板；避开无障碍捷径 |
| **iOS** | **难**（相对产品定义） | 三期或改形态：应用内粘贴译、相册/拍照 OCR、分享扩展；**不承诺全局框选** |
| **鸿蒙** | **受限→难** | 观察系统能力开放；当前勿绑一期里程碑 |

## 4. Win MVP 技术选型草案

**目标：** 单机离线可演示「复制译 + 裁剪译」，中↔英为主。

| 层 | 选型 | 说明 |
|----|------|------|
| Shell | WinUI 3 / WPF 托盘应用，或 Tauri+Rust（二选一，优先团队熟悉度） | 托盘常驻、结果浮层 |
| 热键 | `RegisterHotKey` | 可配置；启动检测冲突 |
| 复制监听 | 隐藏窗 + `AddClipboardFormatListener` | 去抖 ~100–200ms；忽略自身写回 |
| 区域截屏 | **遮罩 Overlay + `GetDC(NULL)`/`BitBlt` 区域拷屏** | 路径短、无黄边纠缠；备选：`IGraphicsCaptureItemInterop::CreateForMonitor` 全屏帧再裁（Win10 1903+） |
| OCR | **RapidOCR + onnxruntime**（PP-OCR 小模型） | 中文优先；可选降级 `Windows.Media.Ocr` |
| 引擎服务 | 本机 **HTTP localhost / Named Pipe** 进程：CTranslate2 加载 OPUS-MT（及后续可替换引擎） | 与 UI 解耦；模型按需下载 |
| Context Layer | 同机库/同服务内模块 | 仅长文或用户开启时介入 |
| LLM | 不进 MVP | 桌面可选插件位预留 |

**串接（裁剪译）：**  
`Hotkey → Overlay 坐标 → BitBlt 位图 → RapidOCR → (可选 Context) → CT2/OPUS → ResultWindow`  

**串接（复制译）：**  
`WM_CLIPBOARDUPDATE → GetClipboardData(CF_UNICODETEXT) → 同引擎链路 → Toast/浮层`

## 5. 风险与未知

| # | 项 | 标记 | 说明 |
|---|----|------|------|
| 1 | Android/iOS 无法对等「复制即译」 | 【已知】 | OS 隐私模型决定；产品话术勿跨端承诺同一体验 |
| 2 | 鸿蒙 `screenshot` 对三方不可用 | 【已知】 | 官方模块说明为系统接口 + `CAPTURE_SCREEN` |
| 3 | Win GDI 截屏 vs 现代 DirectComposition/DRM 窗口 | 【待验证】 | 部分全屏游戏/受保护内容可能黑屏或空帧；演示用办公/浏览器场景即可 |
| 4 | RapidOCR 中文 UI 小字 / 低对比 | 【待验证】 | 需贴真实截图样例集验收 |
| 5 | Play/AppGallery 对「录屏+悬浮窗」组合审查 | 【推测】 | 披露文案与最小权限原则；勿碰无障碍擦边 |
| 6 | CT2/OPUS 中文效果 vs 竞品体感 | 【待验证】 | 已有引擎验收标准；与 Context Layer 联合测 |
| 7 | iOS 未来 ScreenCaptureKit 是否放宽三方全局采集 | 【推测】 | 即使放宽，交互仍偏系统 Picker，难复刻 Win 热键框选 |
| 8 | 杀软/SmartScreen 对「全局钩子+截屏」开源包误报 | 【推测】 | 代码签名与说明页可缓解 |

## 6. 建议里程碑与「演示过关」

### 冻结建议
**立刻冻结 Windows 为第一演示端。** 其余端只做能力跟踪，不阻塞引擎与 Context Layer。

### M0（约 1–2 周）— 骨架
- 托盘常驻；热键弹出框选遮罩；BitBlt 出 PNG  
- 剪贴板文本变更能弹出「收到 N 字」探针  
- 本地 CT2 服务 `/translate` 通英↔中短句  

### M1（约 3–5 周）— 演示过关（验收）
同时满足：
1. **复制译**：浏览器复制一段中/英（≥20 字）→ 2s 内（本机冷启动后热路径）浮层出译文，可一键复制  
2. **裁剪译**：热键 → 框选网页段落 → OCR 原文可读 → 译文呈现；中文界面字样例集主观可用  
3. **长文开关**：粘贴/识别 > 阈值阈值时走 Context Layer，专名不明显乱跳（对照引擎验收标准）  
4. **无云依赖**：断网可完成上述 1–2  
5. **非目标未混入**：无 IME、无视频流字幕、无读屏  

### M2+
- Android：悬浮球 + 用户触发粘贴译 + MediaProjection 框选（独立 UX）  
- OCR/引擎替换插头固化；Win 安装包与模型按需下载
