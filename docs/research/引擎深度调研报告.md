## 1. 摘要（给决策者的 TL;DR）

1. **随译定位**要求：开源免费、轻快、剪贴板/粘贴 + 截屏 OCR；引擎未定；各端薄客户端。  
2. **最匹配「开源免费 + 可选增强」的架构不是单一引擎**，而是：**本地轻量引擎保底（隐私/离线）+ 用户 BYOK 云端高质量（可选）**。【推测：产品形态】  
3. **MVP 默认推荐**：产品内置 **多引擎 BYOK 适配层**（优先接入：微软 Translator / 腾讯云 / 谷歌 / DeepL / 国内 1–2 家），**零自建服务器成本**；未填 Key 时可用 **Firefox Translations / Bergamot 风格本地模型** 做「能用」保底（中英需确认模型是否已发布到 Release）。【已知+推测】  
4. **长期默认推荐**：稳定 **混合架构**——端侧 Opus-MT / Bergamot（经 CTranslate2 或原生）作默认；云端 BYOK 作「增强质量」开关；**不要**把 AGPL 的 LibreTranslate 直接嵌进闭源客户端分发路径而不做合规设计。【已知许可证风险】  
5. **质量**：商业 NMT（DeepL/Google/MS/国内头部）普遍强于开源小模型；LLM 翻译语境好但贵、慢、不稳定；本地量化模型「够用」而非「顶级」。【社区口碑+公开评测片段；完整盲测【待验证】】  
6. **成本**：国内 API 免费额度往往更大（腾讯 500 万字/月、火山 200 万等），国际侧微软 F0 200 万字/月较友好；DeepL API Free **已不可新购**【已知】。  
7. **许可证红线**：NLLB 权重多为 **CC BY-NC** → 商用/应用商店分发风险高；LibreTranslate **AGPL-3.0** → 网络服务改动需提供源码；Argos **代码 MIT** 但 **部分模型许可不清晰**【已知】。  
8. **明确不推荐作核心**：IBM Watson Language Translator（已下线）、单独依赖 NLLB-NC 权重做默认、仅依赖 DeepL Free（不可新购）。  
9. **明天可亲自体验**：DeepL / Google / 微软 / 有道 / 腾讯 / 彩云小译 / Immersive Translate / Bob（见第 7 节）。注意：**产品层 ≠ 引擎层**。  
10. **下一步**：小样本中英盲测（剪贴板短句 + OCR 噪声文本）+ 许可证律师/志愿者复核 + 端侧模型体积/延迟实测。

## 2. 决策标准（随译场景下的权重建议）

| 维度 | 建议权重 | 说明 |
|------|----------|------|
| 与「免费开源 + 轻快」匹配 | 25% | 默认路径不应对用户收费；安装包要轻 |
| 中英等常见语言质量 | 20% | 剪贴板短句、网页片段、OCR 残缺句 |
| 隐私 / 离线 | 15% | 文本是否出设备；无网是否可用 |
| 许可证对开源分发影响 | 15% | 随译要开源分发，AGPL/NC/专有条款会卡死 |
| 成本（项目侧 + 用户 BYOK） | 10% | 项目尽量零服务器；用户 Key 的免费额度体验 |
| 集成复杂度 / 多端 | 10% | Win/安卓/iOS/鸿蒙薄客户端；统一协议 |
| 语言可扩展 | 5% | 先中英，后扩日韩欧 |

**场景匹配加分项**：REST/简单 SDK、单次短文本延迟可控、可批量句子、无强制账号体系。  
**减分项**：必须自建 GPU、安装包 >100MB 才有中英、许可证传染到客户端、无中文文档/无国内可达性。

#### 4.1.1 DeepL API

| 项 | 内容 |
|----|------|

### 4.4 混合架构

**模式**：本地默认（Bergamot/OPUS-CT2）+ 设置页可选 BYOK（DeepL/Google/MS/腾讯/…）+ 可选「仅本地」。

| 优点 | 缺点 |
|------|------|
| 对齐「免费开源」：无 Key 也能用 | 双栈质量不一致，需 UI 标明引擎 |
| 对齐隐私：敏感文本可强制本地 | 端侧集成成本高（尤其移动/鸿蒙） |
| BYOK 满足「要质量」用户 | 模型包下载与更新通道要做 |
| 项目方可零推理服务器 | 许可与模型更新持续维护 |

**【推测】** 该模式是随译与「沉浸式翻译 / Bob」类产品差异化的关键：后两者偏 BYOK 聚合；随译可主打 **开箱本地 + 开源**。

## 5. 许可证风险专节

### 5.1 必须优先处理的风险

1. **NLLB 等 CC BY-NC 权重**  
   - 【已知】非商业许可。随译若上架应用商店、接受捐赠打赏、或公司主体分发，极易踩线。  
   - **建议**：默认引擎黑名单；文档标明「勿内置 NC 权重」。

2. **LibreTranslate AGPL-3.0**  
   - 【已知】网络交互的修改版需提供对应源码。  
   - **建议**：官方若托管，保持 AGPL 合规与商标政策；客户端仅作 API 消费者更安全。不要「复制 LT 代码进专有核心」。

3. **Argos / 部分社区模型「许可不清晰」**  
   - 【已知】存在无 license 字段或训练数据含限制性语料的讨论。  
   - **建议**：白名单模型包；优先 **MPL（Firefox）** 或 **CC BY 4.0（OPUS-MT）** 且 README 清晰者。

### 5.2 相对友好

| 组件 | 许可 | 备注 |
|------|------|------|
| Marian | MIT | 框架 |
| CTranslate2 | MIT | 推理 |
| Bergamot | MPL-2.0 | 修改文件需开源，链接策略相对可控【推测：仍建议法务看 MPL】 |
| OPUS-MT 模型 | 多 CC BY 4.0 | 保留署名 |
| 纯 BYOK 调云 API | 专有 ToS | 不传染随译代码许可，但约束用户 Key 使用 |

### 5.3 开源交付检查清单（建议）

- [ ] 默认捆绑的每个模型文件都有 SPDX/LICENSE  
- [ ] NOTICE/第三方清单可自动生成  
- [ ] 区分「引擎代码许可」与「模型权重许可」  
- [ ] AGPL 组件是否仅作可选后端  
- [ ] 应用商店地区对「开源 + 远程 API」披露

## 6. 推荐方案

### 6.1 MVP 默认（0–3 个月）

**推荐：BYOK 多引擎适配层（必做） + 可选 1 个本地保底（能做就做）**

- **云端优先接入顺序（建议）**  
  1. 微软 Translator（免费额度）  
  2. 腾讯云（国内额度最大档之一）  
  3. 阿里云 / 火山 / 百度（择 1–2）  
  4. Google Cloud（质量/语种，开通重）  
  5. DeepL（质量口碑；注意 Free 不可新购与支付）  
  6. 小牛（日免 + 小语种）  
- **本地保底**：Firefox Translations / Bergamot 中英模型（若 Release 可用）；否则 OPUS-MT zh↔en + CTranslate2 做桌面 POC。  
- **不做**：自建官方 GPU 集群；绑定单一云；默认 NLLB。

### 6.2 长期默认（3–12 个月）

**推荐：混合架构——本地轻量默认 + BYOK 云端增强**

- 默认路径：端侧量化模型（隐私、离线、零费用）  
- 增强路径：用户 Key 一键切换高质量商业引擎  
- 架构上保持「引擎插件化」，各端薄客户端只谈统一 IPC/HTTP  

### 6.3 备选

1. **备选 A**：纯 BYOK 聚合（对标 Immersive Translate / Bob），本地不做——上线最快，但弱化「开源免费开箱」故事。  
2. **备选 B**：官方托管 LibreTranslate（AGPL 合规）+ 客户端指过去——运维与合规成本归项目方，与「不收费」冲突除非捐赠。

### 6.4 明确不推荐及原因

| 对象 | 原因 |
|------|------|
| IBM Watson LT | 服务已撤回 |
| NLLB 作默认内置 | CC BY-NC |
| 仅 DeepL Free | 不可新购 |
| 未量化的大 LLM 端侧默认 | 体积/耗电违背「轻快」 |
| 单一依赖某国内云且无抽象 | 锁定与故障面 |
