# 分句规则

`suiyi_engine.segment` 把剪贴板或截屏 OCR 文本切成句子，供句级翻译（OPUS-MT）使用，也是后续 Context Layer 长文切分的基础。实现只用标准库，不加载模型，也不做语种检测。

公开 API：

```python
from suiyi_engine.segment import Segment, join_segments, split_sentences

segments = split_sentences(text, lang=None, max_chars=400)
translated_text = join_segments(translated_pieces, segments, tgt_lang)
```

`Segment.text` 是去掉首尾空白并完成断行合并后的句子。`start` / `end` 是原文中的半开区间，**按传入字符串的原始码位计算，不做 NFKC**。`trailing` 是本句结束到下一句开始之间的原文（最后一句直到原文末尾）。

没有断行合并时，`text[segment.start:segment.end] == segment.text`。有 OCR 断行或行尾连字符合并时，区间仍覆盖合并前的原文，`text` 是合并后的句子。

## 规则

### 句末

- 中文、日文句末：`。！？!?`。紧跟其后的右引号、右括号（`」』”’）】〉》` 以及 ASCII `"'）)]}`）并入当前句。
- 连续句末标点（`？！`、`！！！`、`。。`）算作同一次句末，不产生空句。
- 日文省略号：`…` 或 `‥` **连用**（两个及以上）视为句末。单个 `…` 不断句。
- ASCII 省略号 `...`（两个及以上的 `.` / `．`）在构成句界时整串并入当前句，不按每个点切开。
- 英文句号 `.` / 全角 `．`：后面是空白，且再往后是大写字母、数字、引号或中日文字时断开；位于文本末尾时，句号属于当前句，不另起空句。句号后直接跟中日文字（中间无空白）也断开。
- 句号后若是小写字母且没有上述句界条件，不断开（例如 `e.g. the note` 里被保护的缩写，或 `hello. world` 这种后接小写的句号）。

### 不切开

下列位置的点号不作为句界：

- 缩写白名单（大小写不敏感）：`Mr. Mrs. Ms. Dr. Prof. Sr. Jr. St. etc. vs. cf. e.g. i.e. a.m. p.m. Ph.D. Inc. Ltd. Co. Fig. Vol. No. Jan.`–`Dec.` 等。
- 大写字母缩写：`U.S.`、`U.K.`、`U.S.A.` 这类 `(大写字母.){2,}`。
- 小数与版本号：`3.14`、`3.11`、`v1.2.3`（点号两侧不是「空白 + 大写」）。
- URL（`http://`、`https://`、`www.`）和邮箱（`name@host`）。保护范围停在空白或中日文字之前，末尾的句号仍可作句界，因此 `See https://example.com/a.b. Next` 会在 URL 后的句号处切开，而不会切在域名内部。

`lang` 不改变上述标点规则。语种检测是另一项工作；这里的 `lang` 只影响换行合并。

### 换行

- 空行（两个及以上换行，或中间只有空白的行）始终分段。`\r\n` 与 `\n` 都算换行，偏移仍落在原始字符串上。
- 单换行，且上一行不以句末标点结束：
  - 上一行末尾是 ASCII `-`，下一行以 ASCII 字母开头：去掉连字符，直接拼接（`long-\nword` → `longword`）。
  - `lang` 为英文：合并为一个空格。
  - `lang` 为 `None` / 中文 / 日文：前后最近的非空字符都是中日文字（汉字、平假名、片假名）时直接拼接，否则合并为一个空格。
- 上一行已经以句末标点结束时，单换行不并进句子，而是留在前一句的 `trailing` 里。

### 超长句

`max_chars` 按 Unicode 码位计数，默认 400。句子更长时，在窗口内最右边的 `；;，,、` 之后切开；窗口内没有这些标点则按 `max_chars` 硬切。切完的每一段都不超过 `max_chars`，也不产生空句。未超过上限的句子不会因为逗号被提前切开。

### 拼接

`join_segments`：

- `trailing` 里含有换行时原样接上，用来还原段落和保留下来的断行。
- `trailing` 只有空格或为空时：目标语 `zh` / `ja`（含 `zh-CN`、`ja-JP` 等）句间不加空格；英文以及其他目标语句间加一个空格。
- 最后一句末尾的纯空格丢掉。末尾换行仍保留。

同语言往返时，把原文和拼接结果都按下述方式去掉多余空白后应当一致：

1. 换行统一成 `\n`（比较时；拼接本身仍保留 `trailing` 里的 `\r\n`）。
2. 行尾 `-\n` 后接 ASCII 字母时去掉连字符和换行。
3. 单个换行夹在两个中日文字之间（可带行首行尾空格）时删掉。
4. 两个及以上换行保留为段落分隔。
5. 段落内部其余空白折叠成一个空格。
6. 去掉句末标点 `.!?。！？` 后面的空格。英文拼接会补上一个空格，中文、日文拼接会去掉空格，比较时都当成多余空白。
7. 目标语为中文或日文时，再去掉 `；;，,、` 后面的空格。

## 已知局限

- 不是统计分句器。白名单外的缩写（如 `Assoc.`）在后接大写时仍可能被切开；白名单内的缩写（如 `No.`、`St.`、`U.S.`）即使后面是新句子也不切开。
- 单个大写首字母加句号（`A. B. Charles`）不保护，`A.` 后接空白和大写时会断开。
- 行尾 ASCII 连字符一律去掉再拼接。`well-known` 被断成 `well-\nknown` 时会变成 `wellknown`。
- 单个 `…` 不断句。`end.Next` 这种句号后没有空白的英文也不断开。
- URL 保护只覆盖连续的 ASCII URL 字符，遇到中日文字即停止。被换行拆开的 URL 可能保护不全。
- 超长硬切按码位计数，可能切在词中间，也不考虑代理对（Python `str` 的一个码位即一个字符）。
- 右书名号 `》` 紧跟句末标点时并入当前句。嵌在括号里的 `！？` 会连同后面的右括号、句号一起结束当前句。
- 不处理西班牙语倒置问叹号等其他语种的句读习惯。`lang` 不会触发这些规则。
- 不做术语表、专名对齐或语种检测。
