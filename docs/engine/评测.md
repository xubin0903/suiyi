# 评测

`scripts/eval_samples.py` 用固定样例集给当前模型打分，供模型选型复核和以后每次改动做回归。它直接调用 `suiyi_engine.translator.Translator`，不经过 HTTP。翻译核心本身不在这里修改；效果问题另开 Issue。

样例集是 [tests/samples/zh_core_v1.jsonl](../../tests/samples/zh_core_v1.jsonl)（见该目录 README）。参考译文目前都是 `draft`。

## 安装

评测依赖在可选组 `eval`，不进运行时，也不进只做翻译的安装：

```bash
pip install -e "engine[eval]"
```

组里是 `sacrebleu` 和 `psutil`。日文 BLEU 若要使用 `ja-mecab`，再装 sacrebleu 的可选分词（其依赖通常包含 MeCab）：

```bash
pip install "sacrebleu[ja]"
```

等价的常见包是 `mecab-python3` 与 `unidic-lite`。没装、或装了但词典不可用时，脚本不会失败，日文 BLEU 回退 `tokenize=char`，并在报告的环境一节写明原因。CI 只安装 `engine[dev,eval]`，不安装 MeCab，也不下载模型。

## 命令

在仓库根目录执行。模型需先按 [模型目录约定](模型目录约定.md) 转成 CTranslate2 int8。

```bash
python scripts/eval_samples.py \
  --samples tests/samples/zh_core_v1.jsonl \
  --models-dir models \
  --out reports/eval-2026-09-25
```

只跑部分方向，或每个方向只取文件里的前 N 条：

```bash
python scripts/eval_samples.py \
  --samples tests/samples/zh_core_v1.jsonl \
  --models-dir models \
  --out reports/eval-zh-en \
  --directions zh-en,en-zh \
  --limit 5
```

| 参数 | 含义 |
| --- | --- |
| `--samples` | JSONL 样例集 |
| `--models-dir` | 已转换模型的根目录 |
| `--out` | 输出目录 |
| `--directions` | 逗号分隔，如 `zh-en,ja-zh`。也接受 `zh→en`。默认跑样例里出现的全部方向 |
| `--limit` | 每个方向最多评测前 N 条（文件顺序）。被截掉的 `clean_id` 不会计入 OCR 差值 |
| `--seed` | 对照样例的随机种子，默认 `0` |

方向顺序固定为 zh→en、en→zh、zh→ja、ja→zh、en→ja、ja→en，然后才是样例里其余方向。

每个方向先 `preload`（中转会加载两段模型），再逐条 `translate`。加载耗时单列；P50 / P95 / max 用的是预热之后的 `elapsed_ms`，不含这次预热。前面方向已经加载过的模型，后面方向的加载耗时会接近 0。

退出码：`0` 成功，`1` 翻译或样例内容错误，`2` 参数或路径错误。

## 输出

`reports/` 已写入根目录 `.gitignore`。不要把生成的 `report.md`、`results.jsonl`、`summary.json` 提交进 git。需要留档的基线表写在本文「基线结果」。

| 文件 | 内容 |
| --- | --- |
| `report.md` | 环境、模型 revision、总表、分方向 × 分类、专名未保留清单、每方向最多 5 条对照 |
| `results.jsonl` | 每条样例的译文、`route`、`route_label`、耗时、chrF、BLEU、专名命中、OCR 差值 |
| `summary.json` | 汇总指标（`schema_version` 为 1），便于以后做回归阈值比对 |

`report.md` 的环境信息包括 CPU 型号、核数、内存、操作系统、Python、ctranslate2、sacrebleu、psutil、引擎版本，以及各模型 `suiyi-model.json` 里的 `hf_revision`。峰值 RSS 是进程高水位：Linux 读 `/proc/self/status` 的 `VmHWM`，Windows 用 `peak_wset`。

中转方向的 route 写成语种路径。ja→zh 没有直连模型，报告中为 `ja→en→zh`，并附上 `opus-mt-ja-en` 与 `opus-mt-en-zh`。

## 指标

分数都来自 sacrebleu，标度是 **0–100**（不是模型卡上有时见到的 0–1 chrF）。

| 指标 | 算法 |
| --- | --- |
| chrF | 主指标。`CHRF()` 默认：去掉空白后的字符 n-gram，`word_order=0`（chrF2）。中文和日文因此按字符计 |
| BLEU | 语料级 `BLEU`。目标语为中文时 `tokenize=zh`，日文为 `ja-mecab` 或回退 `char`，其余为 `13a` |
| 专名保留率 | `must_keep` 里每一项的 `tgt` 是否作为连续子串出现在译文中。大小写敏感，不做 NFKC。空 `tgt` 不算保留。比例是全部项的微平均（保留项数 / 总项数），不是句子平均 |
| OCR chrF 差值 | 对 `ocr_noise` 及其 `clean_id`：`chrF(噪声译文, 参考) - chrF(干净译文, 参考)`，再对方向内取算术平均。负值表示噪声把译文拉离参考 |

chrF / BLEU 只统计参考译文去空白后非空的条目。汇总用的是语料级分数，不是句级分数的平均。`results.jsonl` 里另有句级 chrF / BLEU，方便看单条。

短句往往凑不齐 4-gram，语料级 BLEU 会偏低甚至接近 0。回归比较以 chrF 为主。

延迟的 P50 / P95 在排好序的耗时上做线性插值。`max` 是最大值。

不做 COMET，也不做人工评测流程。报告里的对照样例只供抽查。

指标和编排的单元测试在 `engine/tests/test_eval_metrics.py`、`engine/tests/test_eval_runner.py`。路由、专名和 OCR 差值用假后端，不加载权重。

## 基线结果

本节在本机用 mvp 模型跑完全部六个方向后填入。机器、日期和总表、分方向表以当次 `report.md` 为准。

## 已知限制

- 不改翻译核心，没有术语表或专名一致后处理。专名保留率只反映模型是否碰巧写出了约定译法。
- 参考译文仍是 `draft`，chrF / BLEU 会把合法的另一种译法算成错。
- 日文 BLEU 在没有可用的 `ja-mecab` 时是字符切分，和 MeCab 切分的 BLEU 不能直接比。
- 语料级 BLEU 对短句不稳定；主指标是 chrF。
- OCR 差值要求 `clean_id` 落在同一次评测、同一方向里。`--limit` 截掉干净句时，该条记为缺失，不计入差值。
- 加载耗时是进程内第一次 `preload` 的墙钟时间。六个方向共用已加载的模型，后面的方向不会重复计加载。
- 峰值 RSS 含解释器、全部已加载模型和 sacrebleu，不是单个模型的增量。
- 对照样例由 `--seed` 决定（默认 0），换种子会换那 5 条，汇总分数不变。
- 不做 COMET，也不在脚本里做人工评分。
