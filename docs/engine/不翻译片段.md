# 不翻译片段（#101）

用户反馈：原文里符号、标点多时会乱译；不该翻译的英文也被翻译了，比如 APK 包名 `com.tencent.mm`
（main 上 zh→en 译成 `co.tencent.mm`，单独翻译 `com.tencent.mm` 甚至得到「中文（简体）」）。

本 Issue 在翻译核心里加了「不翻译片段保护」，**默认开启**，作用于所有语向（含英文中转）。
结果均为 **Linux 实测**（`MKL_ENABLE_INSTRUCTIONS=AVX512_E1`、`taskset -c 0-3`、beam 2、int8），
**Windows 待测**。

## 开关

| 设置 | 写法 | 默认 |
|------|------|------|
| 服务默认 | `serve --verbatim` / `--no-verbatim`，或环境变量 `SUIYI_VERBATIM=1/0`（规则同 `SUIYI_GLOSSARY`） | 开启 |
| 单次请求 | `/translate` 请求体 `"verbatim": true/false`；`/ocr_translate?verbatim=false` | 用服务默认 |
| 状态 | `/health` 的 `verbatim_enabled` | — |

详见 [HTTP API](HTTP-API.md)。关掉后不切块、不找片段、分句规则不变，行为与 main 相同；唯一的全局改动是中文译文句末 emoji 后的半角 `.` 改成 `。`。

## 处理流程

1. **按行 / 块切分**（`verbatim.split_blocks`）。下面这些整块照抄，**不送模型**：
   - 围栏代码块（```` ``` ```` / `~~~`），包括里面的注释；
   - 代码行：以 `;` `{` `}` `)` 结尾或含赋值的代码、`def` / `class` / `import` / `return` / `if (...)` 等关键字行、
     SQL；
   - 命令行整行（`git clone …`、`cd y`、`pip install -e .`、`$ ` / `> ` 提示符开头）；
   - JSON / YAML 行（`"key": …`、`key: value` 形式的配置行、`- item`、括号行）；
   - 堆栈行（`at com.x.Y.z(Y.java:42)`、`File "...", line 12`、`Traceback …`、`... 12 more`）和紧随其后的异常行；
   - 注释行（`#` / `//`）只有挨着代码行时才算代码，单独出现时按普通文字翻译。
   - 日志行的「时间戳 + 级别 + 线程 / logger」前缀照抄，后面的消息照常翻译；Markdown 的列表、标题、引用标记照抄。
2. **整段没有要翻译的块时原样返回**：`text` 与原文逐字相同，`route` 为空，不加载模型。语向仍先按已装模型校验，
   没有模型的语向照旧返回 `unsupported_pair`。
3. 要翻译的块照常分句。每句用正则找出**行内片段**（`verbatim.find_spans`）：包名、全限定类名、
   驼峰 / 下划线 / 帕斯卡标识符、`foo(bar)`、Windows / Unix 路径、URL、邮箱、版本号、命令与参数
   （`--flag=value`、`git rebase -i HEAD~3`）、环境变量（`$HOME`、`%APPDATA%`、`${X}`、`$env:X`）、
   哈希 / UUID / `0x…`、行内代码、行内 JSON、HTML 标签、正则、错误码（`ERR_…`、`E1234`、`CVE-…`）、emoji。
4. 每句按下面的顺序保证片段逐字出现在译文里（`terms.translate_with_terms`，复用 #83 的占位符机制）：
   1. 整句只剩片段和标点：直接照抄，不送模型；
   2. 先正常翻译（有术语要保护的句子，片段和术语一起换成占位符，与原句同批翻译）；片段都原样出现就用它，
      模型的语序最自然。实测大部分句子在这一步就通过；
   3. 否则**只把第一遍丢了的片段**换成占位符再翻一遍（占位符越少，越不容易出现 #89 / #97 里多出「型」、
      重复、语序乱的问题）；还原失败、出现新的重复、仍缺片段都视为失败；
   4. 降级：一句片段多于 8 个（`MAX_VERBATIM_SLOTS`）直接跳过第 3 步；第 3 步失败时按片段切开，
      只翻译片段之间的文字再按原顺序拼回。这一步一定保留片段，但语序可能不如整句自然。
5. 目标语为中文时：#97 的标点规范化跳过片段内部（`connect(host, port)` 里的半角逗号不改）；
   以 ASCII 开头 / 结尾的片段紧贴汉字时补一个空格（emoji 和 HTML 标签不加）；句末 emoji 后的半角 `.`
   改成 `。`。

### 分句

开启时，片段内部的 `?` `!` `.` 不再当句末（例如正则 `(?i)error|fatal` 在 main 上会被切成两句）。

### 防误伤

- 句末和缩写里的点不算片段：`e.g.`、`i.e.`、`p.m.`、`Mr.`、`word.`、`10.30`、`3.5`；
- `PNG/JPEG`、`read/write`、`file(s)`、`Status: done`、`macOS`、`iPhone`、Markdown 标题（`# Installation`）不算；
- `cd`、`make`、`find`、`unzip`、`pod`、`nginx` 等同时是英文单词或太短的命令名，只有后面紧跟像代码的参数，
  或出现在行首、中文后、冒号 / 反引号后、`run` / `运行` 之后才算命令（「unzip them」「The pod restarts」不算）；
- 命令片段遇到英文功能词（to、and、then、if…）就结束，不会把后半句吞掉。

这些都有单测（`engine/tests/test_verbatim.py`）。

### 为什么代码块里的注释也不翻译

代码块是拿来复制运行的，改了注释会让译文里的代码和原文对不上；单独一行注释缺上下文，模型容易译错，
还可能改动注释符号、缩进和行尾。只翻译代码块外的说明文字。日志消息正文则照常翻译，因为那是给人看的句子。

## 已知限制

- 规则识别，没覆盖的写法照常送模型；片段本身保住了，但周围的译文质量仍取决于模型（例如 `lint` 被译成「皮带」）。
- 按片段切开翻译的句子语序可能生硬（逐条对比见 PR）。
- 代码块里的注释、日志行里异常类名后的消息（`NullPointerException: boom`）不翻译。
