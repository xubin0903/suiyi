用户实测反馈交互没问题，翻译质量是核心短板：`container orchestration engine` 被译成「集装箱管弦发动机」。
本文记录 #78 的三件事：专业领域测试集、候选模型对比、术语保护原型。**默认引擎不改**；
是否引入 LLM 由负责人和用户决定，LLM 类候选只作为对照项评测，不接入默认引擎。

结论的标注：**已测**＝本文数据在评测机上实际跑出；**推测**＝根据上游文档、模型卡或经验判断，未实测；
**待验证**＝需要别的环境（Windows 笔记本、GPU 等）才能确认。

## 指标

| 指标 | 说明 |
| --- | --- |
| chrF / BLEU | sacrebleu 语料级，0–100。中文 BLEU 用 `zh` 分词，日文用 `ja-mecab`（不可用时回退 `char`）。报告以 chrF 为主 |
| COMET | Unbabel/wmt22-comet-da（Apache-2.0）。需要 torch，只在评测机上另跑，不进运行时与 CI |
| 术语准确率 | 原文里匹配到的术语中，译文按术语表写法（含列出的等价变体）出现的比例。规则见 `suiyi_engine/glossary.py` |
| 分领域 | en→zh、zh→en 按领域分别给 chrF 与术语准确率 |
| 延迟 | 单条 P50 / P95（ms），句子与段落分开；每个方向先预热一条，不计入 |
| 加载 | 从构造到可翻译的耗时（LLM 为启动 llama-server 到 `/health` 就绪） |
| 内存 | 进程 RSS（MB）。CTranslate2 类在评测进程内：常驻 = 结束时 RSS − 加载前 RSS，峰值 = VmHWM − 加载前 RSS；LLM 类取 llama-server 子进程的 RSS / VmHWM |
| 体积 | 候选用到的模型文件在磁盘上的总大小 |

## 怎么跑

依赖：`pip install -e "engine[eval]"`（sacrebleu、psutil）。CTranslate2 候选需要先转成 int8（见下文「候选的获取」），
LLM 候选需要 llama.cpp 的 `llama-server`。

```bash
# 快速子集（每个方向 × 领域取 2 句 + 1 段，日文方向最多 8 条，并总是包含典型译例），约 80 条
python scripts/eval_domain.py run --candidate opus-mt --quick \
  --models-dir /path/to/models --out reports/domain --threads 4

# 全量 388 条；LLM 候选要给 llama-server 路径
python scripts/eval_domain.py run --candidate hy-mt1.5-1.8b \
  --models-dir /path/to/models --out reports/domain --threads 4 \
  --llama-server /path/to/llama-server

# 多个结果合成对比报告
python scripts/eval_domain.py report reports/domain/*.json --out reports/domain/report.md
```

`--directions en-zh,zh-en` 只跑部分方向，`--limit N` 每个方向只取前 N 条。候选清单是
`engine/eval/domain/candidates.json`，模型路径相对 `--models-dir`。

评测机上的约定：`taskset -c 0-3` 限 4 核、`--threads 4`，候选依次跑，不并行。

**评测机注意事项（已测）**：评测机是带 AMX 的 Xeon KVM 虚拟机。MKL 的 AMX int8 GEMM 在这台机器上结果不稳定：
同一句 opus-mt-en-zh int8 连跑 30 次，4 线程时 30 次输出各不相同，大多夹杂乱码；另有进程占用 CPU 时，单线程 30 次里也有 1 次乱码。
float32 或者 `MKL_ENABLE_INSTRUCTIONS=AVX512_E1`（关掉 AMX，保留 VNNI）时，30 次全部一致。
因此本文所有 CTranslate2 数据都在 `MKL_ENABLE_INSTRUCTIONS=AVX512_E1` 下测得，结果 JSON 的 `environment` 里记有取值。
推测是虚拟机没有正确保存 AMX tile 状态，与模型无关；普通笔记本 CPU 没有 AMX，不受影响（推测）。
在带 AMX 的服务器上部署引擎时是否要默认关掉，另开 Issue 讨论。

CI（ubuntu-latest）只跑现用基线 opus-mt 在 en↔zh 上的快速子集，用来证明脚本能跑通；报告写进 job summary，
结果 JSON 作为 artifact 上传。runner 的耗时不作为性能数据。

### 候选的获取

CTranslate2 候选（需要 `convert` 可选组所在的 venv，与运行时分开）：

```bash
# Hugging Face 上的 seq2seq 模型
ct2-transformers-converter --model facebook/m2m100_418M --output_dir cand/m2m100-418m \
  --quantization int8 --low_cpu_mem_usage --copy_files sentencepiece.bpe.model
# m2m100_1.2B、nllb-200-distilled-600M / 1.3B 同理；opus-mt-tc-bible-big-zhx-en 拷 source.spm target.spm
```

en→zh 与 ja→zh 两个 tc-big 模型是多目标模型，句首要加 `>>cmn_Hans<<`，清单里已配置。
