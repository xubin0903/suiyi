# 模型目录约定

翻译服务用 CTranslate2 加载 OPUS-MT。原始权重在 Hugging Face 上是 Transformers（Marian）格式，由 `scripts/convert_models.py` 下载固定 revision 并量化。模型文件只留在本机，不进 git。运行时由 `suiyi_engine.translator` 按这里的目录和 `suiyi-model.json` 懒加载，见 [翻译核心](翻译核心.md)。M4 的按需下载复用同一布局。

## 输出目录

默认根目录是仓库根 `models/`。若设置了环境变量 `SUIYI_MODELS_DIR`，则用该路径。`--out-dir` 优先于环境变量。

```
<models_dir>/<model_id>/
  model.bin                 CTranslate2 权重
  config.json               CTranslate2 配置
  shared_vocabulary.json    或 shared_vocabulary.txt，或 source/target 词表（依转换器输出）
  source.spm                SentencePiece 源语言模型
  target.spm                SentencePiece 目标语言模型
  vocab.json                源仓库词表（若快照中存在则拷入）
  suiyi-model.json          随译元数据
```

CTranslate2 4.8.2 转换示例清单里的两个 Marian 模型时，词表文件名是 `shared_vocabulary.json`。脚本同时接受文件名中带 `vocabulary` 的输出，以及 `vocab.json` / `source.vocab` / `target.vocab`。

`<model_id>` 是清单字段 `id`（例如 `opus-mt-zh-en`），不是 Hugging Face 仓库名。转换过程写在 `<models_dir>/.<model_id>.partial`，成功后才改名为正式目录。失败时删除半成品，已完成的其他模型目录保留。

## suiyi-model.json

内容是清单条目的全部字段（多出来的字段也原样保留），再加上下面四项：

| 字段 | 含义 |
|------|------|
| `quantization` | 本次使用的量化，默认 `int8` |
| `ctranslate2_version` | 转换时安装的 CTranslate2 版本 |
| `converted_at` | 转换完成时间，ISO 8601，带时区（UTC，形如 `2026-09-25T00:00:00+00:00`） |
| `files` | 文件名 → `{ "sha256": "<64 位十六进制>", "bytes": <字节数> }` |

`files` 不包含 `suiyi-model.json` 自身。哈希在写入元数据之前计算。

目标目录已存在，且其中 `suiyi-model.json` 的 `hf_revision`、`quantization` 与本次参数一致，并且 `model.bin` 还在，则打印「已存在」并跳过。`--force` 会重新下载并转换；新结果写完后才替换旧目录，中途失败不删除上一版成功结果。

目录已存在但 revision 或量化不一致时，脚本非零退出并提示加上 `--force`，不会悄悄覆盖。

## 上游 Marian zip 来源（weights_source）

清单条目带 `weights_source` 时，不走 Hugging Face，而是下载 Helsinki-NLP 在 `object.pouta.csc.fi` 发布的原始 Marian zip（Issue #25：HF 上的 zh→ja 转换版丢了源语词表，en→ja 选中的那一版 HF 上没有）。这类条目的 `hf_repo`、`hf_revision` 为 `null`。

```json
"weights_source": {
  "type": "opus-mt-zip",
  "url": "https://object.pouta.csc.fi/Tatoeba-MT-models/zho-jpn/opusTCv20210807-sepvoc_transformer-big_2022-07-28.zip",
  "sha256": "bee6b96f9ab1abe50808374d926c2211798a2437ed684d700fc37f5da4d7d1da",
  "model_file": "opusTCv20210807-sepvoc.spm32k-spm32k.transformer-big.model1.npz.best-perplexity.npz",
  "vocab_files": ["opusTCv20210807-sepvoc.spm32k-spm32k.src.vocab", "opusTCv20210807-sepvoc.spm32k-spm32k.trg.vocab"],
  "copy_files": ["source.spm", "target.spm", "LICENSE", "README.md"]
}
```

| 字段 | 含义 |
|------|------|
| `type` | 只支持 `opus-mt-zip` |
| `url` | 必须在 `https://object.pouta.csc.fi/` 下，以 `.zip` 结尾 |
| `sha256` | 整个 zip 的 sha256。下载后不符即失败，不留半成品 |
| `model_file` | zip 里的 Marian `.npz` |
| `vocab_files` | 1 个（共享词表）或 2 个（源、目标分离词表）。一行一个 token 的 `.vocab` 会先改写成 CTranslate2 能读的 YAML；`.yml` 原样使用 |
| `copy_files` | 转换后拷进模型目录的文件，必须含 `source.spm`、`target.spm`。清单里的两颗都把 `LICENSE`（CC BY 4.0 全文）和 `README.md` 一起拷入，随模型分发 |

- zip 缓存在 `<models_dir>/.cache/<sha256>.zip`（以 `.` 开头，运行时扫描会跳过）。缓存命中且哈希一致时不再下载；`--force` 会复用缓存重新转换。确定不再需要时可以手动删除 `.cache/`。
- 只解出上面列出的文件，放在 `<models_dir>/.<model_id>.work`，结束后删除。
- 转换用 `ctranslate2.converters.MarianConverter`，不需要 torch / transformers。不过 `convert` 可选组仍会一起装上，HF 条目要用。
- 「已存在」判断改用 `sha256:<hex>` 代替 `hf_revision`；`suiyi-model.json` 里保留整个 `weights_source`。
- 分离词表模型转换后的目录是 `source_vocabulary.json` + `target_vocabulary.json`，共享词表是 `shared_vocabulary.json`。

| 模型 id | 量化 | 目录大小 |
|---------|------|----------|
| `opus-mt-zho-jpn-tc-big-2022-07-28` | int8 | 221,744,449 字节（zip 776,428,705 字节） |
| `opus-mt-eng-jpn-2021-02-18` | int8 | 85,765,966 字节（zip 289,140,267 字节） |

## 安装转换依赖

依赖在 `engine/pyproject.toml` 的可选组 `convert`：`ctranslate2`、`huggingface_hub`、`sentencepiece`、`transformers`、`torch`。运行时依赖不包含 `torch` 和 `transformers`。只做 lint / 单元测试时安装 `engine[dev]` 即可。CI 的 lint / 单元测试不需要 `convert`；只有 Linux 上的专业领域评测快速子集（#78）会在单独的 venv 里装 `convert`，转换 `opus-mt-en-zh` / `opus-mt-zh-en` 并用 actions/cache 缓存，运行环境仍不含 torch / transformers。

`torch` 用 CPU 版即可。先装 CPU 轮子，再装转换组，避免 pip 改拉体积更大的默认轮子。

### bash

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -U pip
pip install torch --index-url https://download.pytorch.org/whl/cpu
pip install -e "engine[convert]" --upgrade-strategy only-if-needed
```

lint 和单元测试另外需要：

```bash
pip install -e "engine[dev]"
```

### Windows PowerShell

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -U pip
pip install torch --index-url https://download.pytorch.org/whl/cpu
pip install -e "engine[convert]" --upgrade-strategy only-if-needed
```

PowerShell 里方括号必须加引号。

## 转换命令

在仓库根目录执行。下载使用清单里的 `hf_revision`（40 位小写 commit sha），不会跟着 `main` 浮动。同一仓库里的 TensorFlow / Flax / Rust 权重不会下载。

正式清单路径是 `engine/model_manifest.json`（模型选型 Issue 的交付物）。它合并进 `main` 之前，用示例清单 `engine/model_manifest.example.json`。示例只含 `opus-mt-zh-en` 和 `opus-mt-en-zh`，两行都是 `tier: "mvp"`，用来开发转换脚本，不代替正式选型结论。

### bash

```bash
# 列出示例清单
python scripts/convert_models.py --manifest engine/model_manifest.example.json --list

# 转换一个模型
python scripts/convert_models.py --manifest engine/model_manifest.example.json --ids opus-mt-zh-en

# 转换示例清单中全部 mvp 模型
python scripts/convert_models.py --manifest engine/model_manifest.example.json --tier mvp

# 已存在且 revision、量化一致时会打印「已存在」并跳过；--force 重新生成
python scripts/convert_models.py --manifest engine/model_manifest.example.json --ids opus-mt-zh-en --force
```

### Windows PowerShell

```powershell
python scripts/convert_models.py --manifest engine/model_manifest.example.json --list
python scripts/convert_models.py --manifest engine/model_manifest.example.json --ids opus-mt-zh-en
python scripts/convert_models.py --manifest engine/model_manifest.example.json --tier mvp
python scripts/convert_models.py --manifest engine/model_manifest.example.json --ids opus-mt-zh-en --force
```

常用参数：

| 参数 | 默认 | 作用 |
|------|------|------|
| `--ids` | 无 | 只转换列出的模型 id |
| `--tier` | 无 | 转换该 tier 的全部模型（`mvp` 或 `optional`） |
| `--manifest` | `engine/model_manifest.json` | 清单路径 |
| `--out-dir` | `SUIYI_MODELS_DIR`，否则仓库根 `models/` | 输出根目录 |
| `--quantization` | `int8` | CTranslate2 量化 |
| `--force` | 关闭 | 覆盖已存在的同 revision、同量化结果 |
| `--list` | 关闭 | 只打印清单，不下载 |

`--ids` 和 `--tier` 互斥，必须指定其中一个（`--list` 除外）。

## 和正式清单对接

模型选型合并 `engine/model_manifest.json` 之后：

1. 去掉 `--manifest`，或继续显式传入 `engine/model_manifest.json`。
2. `python scripts/convert_models.py --tier mvp` 会转换正式清单里全部 `tier: "mvp"` 的模型，不限于示例里的中英两向。
3. 清单可以带 Issue 规定字段之外的键（体积、架构、备注等）。转换脚本不丢字段，会写入 `suiyi-model.json`。
4. `pivots` 只被校验为数组，中转路由不在本脚本实现。
5. 不要把示例清单改名为正式清单，也不要在转换 PR 里提交 `engine/model_manifest.json`，以免和模型选型冲突。

`hf_revision` 必须是 40 位小写 commit sha。写成 `main` 或标签名时，脚本会直接拒绝。

## 实测磁盘大小

下表是示例清单里两个 mvp 模型转为 `int8` 之后，整个模型目录的大小（含 `suiyi-model.json`、SentencePiece 和词表）。测量环境：Python 3.12.3、CTranslate2 4.8.2、transformers 5.17.0、torch 2.14.0+cpu，2026-09-25。

```bash
du -sb models/opus-mt-zh-en models/opus-mt-en-zh
```

| 模型 id | 量化 | 目录大小 |
|---------|------|----------|
| `opus-mt-zh-en` | int8 | 84,102,501 字节（`du -sh` 为 81M） |
| `opus-mt-en-zh` | int8 | 84,102,206 字节（`du -sh` 为 81M） |

其中 `model.bin` 各为 79,567,635 字节。Hugging Face 上的 `pytorch_model.bin` 约 300MB，且同一仓库还有 tf/flax/rust 副本。转换脚本只取 PyTorch 权重和分词文件，上表是量化后的目录，不是原始仓库体积。

转换时 Transformers 可能打印 `torch_dtype` 弃用警告，并建议安装 `sacremoses`。不安装 `sacremoses` 也能完成转换。`sacremoses` 不在 `convert` 依赖里。

## OCR 模型目录（#51）

OCR 模型不是语种对，不走 `suiyi-model.json`，统一放在模型根目录下的 `ocr/` 子目录。翻译服务扫描时只认含 `suiyi-model.json` 的子目录，所以 `ocr/` 不会被当成翻译模型。

```
<models_dir>/ocr/
  PP-OCRv6_det_small.onnx               检测
  PP-OCRv6_rec_small.onnx               识别（中/英/日同一个模型，字典在 ONNX 元数据里）
  ch_ppocr_mobile_v2.0_cls_mobile.onnx  方向分类（默认关闭，但 RapidOCR 仍要求文件存在）
  suiyi-ocr.json                        来源、哈希与推荐组合
```

文件名与 `engine/ocr_model_manifest.json` 的 `file` 字段一致，也与 RapidOCR 上游文件名一致。`suiyi-ocr.json` 记录目录里每个校验通过的文件的 `id`、`task`、`sha256`、`bytes`、`url`、`license`，以及 `recommended` 和 `rapidocr_requirement`。

下载（只在开发期联网，逐个校验 sha256 与字节数，不符即删除半成品并失败）：

```bash
python scripts/download_ocr_models.py                  # 推荐组合，约 31.7 MB
python scripts/download_ocr_models.py --all            # 清单里的全部候选
python scripts/download_ocr_models.py check            # 只检查本地，不联网
```

```powershell
python scripts\download_ocr_models.py --models-dir C:\path\to\models
```

运行时不会联网下载：必须给 RapidOCR 的 det/cls/rec 各传一个本地 `model_path`，缺文件时直接报出缺失的模型 id。原因与验证方式见 [OCR 选型与许可证](OCR选型与许可证.md#离线与关闭自动下载)。

## 不要把权重提交进 git

仓库根 `.gitignore` 已忽略 `/models/` 以及 `*.bin`、`*.onnx`、`*.gguf`、`*.argosmodel`。转换结束后在仓库根执行 `git status`，不应出现模型文件。Hugging Face 缓存默认在用户目录（`~/.cache/huggingface`），不在仓库里。

单元测试替换下载和转换，不访问网络。带 `@pytest.mark.model` 的冒烟翻译只在 `SUIYI_MODELS_DIR` 指向已有目录、且其中已经有转换好的 `opus-mt-zh-en` 时运行，否则跳过。CI 不要为了测试去下载权重。
