# 翻译核心

`suiyi_engine.translator.Translator` 是与 HTTP 无关的同步翻译入口。评测、性能基准和 [本机 HTTP API](HTTP-API.md) 都调用它。本模块不做语种自动检测，也不做术语表或上下文窗口。

## 适配层

`suiyi_engine.backends.base.TranslationBackend` 只有一个方法：

```python
def translate_batch(self, sentences: list[str]) -> list[str]: ...
```

每个实例对应一个模型目录、一个方向。当前实现是 `Ct2OpusBackend`（CTranslate2 + SentencePiece）。以后的 Bergamot 等后端实现同一方法即可替换，调用方不引用 CTranslate2。

## 模型从哪里来

`Translator(models_dir)` 的目录默认是环境变量 `SUIYI_MODELS_DIR`，否则是仓库根 `models/`。启动时只扫描子目录里的 `suiyi-model.json`（以 `.` 开头的转换半成品目录忽略）。权重在该模型 id 第一次被用到时加载，并缓存在进程内。`preload([(src, tgt), ...])` 用于启动预热。并发第一次加载同一个 id 只会构造一次后端。

CTranslate2 固定 `device="cpu"`、`compute_type="int8"`（须与元数据里的 `quantization` 一致）。线程默认 `inter_threads=1`、`intra_threads=min(4, os.cpu_count())`，拿不到 CPU 数时为 2（#87；此前为 `min(2, CPU 数)`）。`serve` 还可以用环境变量 `SUIYI_INTRA_THREADS` 覆盖，优先级是命令行 > 环境变量 > 默认。`beam_size` 默认 2，`max_batch_size` 默认 32。`python -m suiyi_engine serve` 可以用 `--intra-threads`、`--beam-size`、`--max-batch-size` 覆盖；不传则用这里的默认。`torch` 和 `transformers` 不是运行时依赖。

`src_prefix_token` 非空时（en→zh 为 `>>cmn_Hans<<`），作为源 token 序列的第一个 token，不交给 SentencePiece 再切。源序列末尾补 `</s>`。批量翻译前按句长排序以减少 padding，输出再还原成原顺序。反分词后去掉 `▁` 和 `>>id<<`；中文、日文目标语去掉字与字、字与中日标点之间的空格，拉丁字母两侧的空格保留。

## 路由

语种代码收成 ISO 639-1 小写二字母（`zh-CN` → `zh`）。`auto` 会直接报错，由调用方先做语种检测。

1. `src == tgt`：原样返回，`route` 为空，不加载模型。
2. 该方向已经安装了模型：直连，`route` 长度为 1。同一方向有多份目录时，优先 `engine/model_manifest.json` 里的 id。
3. 清单把该方向定为直连、但目录里还没有：抛 `UnsupportedPairError`，`missing_ids` 是清单中的模型 id。**不会**改走英文中转。因此 zh→ja 在 `opus-mt-zho-jpn-tc-big-2022-07-28` 未安装时失败，即使 `zh→en` 和 `en→ja` 已经在。
4. 清单 `pivots` 声明了中转（目前只有 ja→zh，经 en，legs 为 `opus-mt-ja-en` 再 `opus-mt-eng-zho-tc-big-2022-05-14`）：两段都安装了才走，`route` 长度为 2。缺哪一段，错误里就列哪一个 id。某一段没装时，可以用**清单里列出的**同方向模型顶替（#83：只装了旧的 `opus-mt-en-zh` 时用它做第二跳）；清单之外的自定义模型不能顶替。
5. 清单既没有直连也没有中转，但 `src→en` 与 `en→tgt` 都已安装：经英文中转。都没有则错误信息里带上清单中对应的模型 id。

空白文本返回空字符串，不检查模型是否已下载。

## 术语保护与句末标点（#83）

`Translator(..., glossary=GlossaryStore(...))` 在 zh↔en **直连**时做术语保护：原句和「术语换成占位符」的版本放进同一批解码，原句译文里术语已经正确就用原句，否则用占位符版并还原成术语表里的译法；占位符丢失或重复时回退为原句译文。`translate` / `translate_many` 的关键字参数 `glossary=True/False` 单次覆盖默认开关。其他语向和英文中转不做术语保护。详见 [术语保护](术语保护.md)。

所有方向都做句末标点补全：原文以句末标点结尾、译文以字母 / 数字 / 汉字结尾时补上（中日 `。！？`，其他 `.!?`），省略号不补；中日译文里汉字后面的半角 `.!?` 改成全角。

清单推荐的模型没装、目录里有同方向的旧模型时（如只有 `opus-mt-en-zh`），第 2 步照常直连旧模型；`ModelRegistry.outdated()` 列出这些方向，`serve` 启动时据此告警。

## 长文

`split_sentences` 按源语切句，整批送给后端，再用 `join_segments` 按目标语拼回（中日句间不加空格，英文加一个空格，含换行的分隔原样保留）。英文中转时两跳句子一一对应，中间结果不再分句，避免和原文段落错位。

```python
result = Translator().translate("今天天气很好。我们去公园吧。", "zh", "en")
result.text       # 译文
result.route      # ["opus-mt-zh-en"] 或中转时的两个 id
result.elapsed_ms
```

`translate_many` 翻译多段文本。语向不可用时，在返回任何一段之前失败。

命令行：

```bash
python -m suiyi_engine translate --src zh --tgt en "今天天气很好。我们去公园吧。"
```

## 测试

路由、中转、拼接、懒加载和并发用假后端，不需要权重。真实模型用 `@pytest.mark.model`：未设置 `SUIYI_MODELS_DIR` 或目录不存在时跳过，CI 不下载模型。

## 已知限制

- 本模块不做 HTTP（见 [HTTP API](HTTP-API.md)），不做 `src="auto"`（由 HTTP 层检测后传入具体语种），不做术语表 / 专名一致 / 上下文窗口。
- 一期只保证 CPU + int8。`device` 可以传入别的值，但没有 GPU 路径和测试。
- 中转只实现 `via: en`，且中间英文不再分句。
- 清单已指定直连模型时，该模型未下载就不会自动改走中转。
- 首次加载模型的时间算进那一次 `translate` 的 `elapsed_ms`。不同模型的第一次加载共用一把锁，会互相等待。
- 默认模型目录按源码布局解析（`engine/src/suiyi_engine` 向上到仓库根）。安装成 wheel 后应设置 `SUIYI_MODELS_DIR`。
