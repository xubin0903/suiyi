# M4：Windows 便携包（第一刀）

面向 v0.1 发布的**便携 zip 骨架**：解压后运行 `Suiyi.exe`，由客户端拉起同目录下的打包引擎。托盘与进程监管沿用现有实现，不重做。模型与 OCR **不**打进包，按需下载（见 [模型目录约定](../engine/模型目录约定.md)）。

相关 Issue：#127。

## 目录布局

```
Suiyi/                              # 解压根 = 客户端 BaseDirectory
  Suiyi.exe                         # dotnet publish 产物
  *.dll / runtimes/ …
  engine/
    suiyi-engine.exe                # 引擎 PyInstaller（或等价）产物；本期可由占位 README 代替
    _internal/ …                    # onedir 依赖（若采用 onedir）
    README.txt                      # 无 exe 时的说明
  models/
    README.txt                      # 空目录说明；实际权重按需放入
  settings.portable.example.json    # 示例：相对路径指向引擎与 models
```

设置文件默认仍是 `%APPDATA%\suiyi\settings.json`。便携调试可设：

```powershell
$env:SUIYI_CONFIG_DIR = "D:\Suiyi\config"
$env:SUIYI_LOG_DIR = "D:\Suiyi\logs"
```

## 启动引擎的方式

`EngineCommandResolver` 优先级（命中即用）：

1. 设置 `engine.command` + `engine.args`（相对路径相对 **Suiyi.exe 所在目录**）
2. 同目录下存在 `engine\suiyi-engine.exe` 时自动使用（无需改设置）
3. `engine.pythonPath` → 仓库 `.venv` → `py -3.11` / PATH 上的 `python`（开发态）

实际参数一律追加：

```text
serve --port <port> --preload <preload> [--preload-ocr] [--models-dir <dir>]
```

与开发态 `python -m suiyi_engine serve …` 同一套 CLI。因此打包后的 `suiyi-engine.exe` 必须接受相同的 `serve` 子命令。

### 示例 settings（便携）

把 `client/packaging/settings.portable.example.json` 里 `engine` 段合并进设置，或整份作参考：

```json
"engine": {
  "port": 18780,
  "command": "engine\\suiyi-engine.exe",
  "args": null,
  "modelsDir": "models",
  "preload": "zh-en,en-zh",
  "preloadOcr": true
}
```

未写 `command`、但包内已有 `engine\suiyi-engine.exe` 时，客户端也会自动发现。开发树里没有该文件时行为与 M3 相同（走 Python）。

## 如何 publish 客户端

在仓库根目录。需要 [.NET 8 SDK](https://dotnet.microsoft.com/download)；目标机器若用框架依赖发布，还需 [.NET 8 Desktop Runtime](https://dotnet.microsoft.com/download/dotnet/8.0)。

### 框架依赖（CI 默认，体积小）

```powershell
# Windows PowerShell
.\client\packaging\publish-portable.ps1 -OutputDir .\artifacts\suiyi-portable
```

```bash
# bash（Linux 上 EnableWindowsTargeting 可产出 win-x64 文件，不能本机运行）
./client/packaging/publish-portable.sh ./artifacts/suiyi-portable
```

等价手动命令：

```bash
dotnet publish client/src/Suiyi.App/Suiyi.App.csproj -c Release -r win-x64 --self-contained false \
  -o ./artifacts/suiyi-portable
mkdir -p ./artifacts/suiyi-portable/engine ./artifacts/suiyi-portable/models
cp client/packaging/engine/README.txt ./artifacts/suiyi-portable/engine/
cp client/packaging/models/README.txt ./artifacts/suiyi-portable/models/
cp client/packaging/settings.portable.example.json ./artifacts/suiyi-portable/
```

### 自包含（用户机可不装 .NET Runtime）

```powershell
.\client\packaging\publish-portable.ps1 -OutputDir .\artifacts\suiyi-portable -SelfContained
```

## 引擎 exe（需引擎侧交付）

| 项 | 约定 |
|----|------|
| 工具 | 优先 PyInstaller **onedir**（排错容易）；稳定后再评估 onefile |
| 文件名 | `suiyi-engine.exe`，放在便携根的 `engine\` |
| CLI | 与 `python -m suiyi_engine` 相同：`suiyi-engine.exe serve --port 18780 …` |
| 依赖 | 运行时不得带 torch/transformers；ctranslate2 原生库打进 onedir |
| 模型 | **不**打进包；读 `--models-dir` 或工作目录下 `models/` |
| 工作目录 | 客户端在无仓库根时用解压根作 WorkingDirectory |

冒烟（Windows，引擎产物就位后）：

```powershell
.\engine\suiyi-engine.exe serve --port 18780
# 另开终端
Invoke-RestMethod http://127.0.0.1:18780/health
```

客户端联调：将 exe 放入 publish 输出的 `engine\`，启动 `Suiyi.exe`，托盘应进入就绪（可先不预加载模型，或按文档转换 mvp 模型到 `models\`）。

## 模型 / OCR 按需下载

- **不要**把权重打进安装包或 zip（[CONTRIBUTING](../../CONTRIBUTING.md)）。
- 布局与开发态相同，见 [模型目录约定](../engine/模型目录约定.md)。
- 客户端 `Suiyi.Core.Packaging.IModelProvisioner` / `StubModelProvisioner` 为占位：完整下载 UI 后续 Issue。当前请用：

```powershell
python scripts\convert_models.py --tier mvp --out-dir D:\Suiyi\models
python scripts\download_ocr_models.py --models-dir D:\Suiyi\models
```

浮窗已有「未安装语向模型 / OCR 模型未安装」提示，可指引用户按文档操作。

## CI 制品

`.github/workflows/ci.yml` 的 `client（windows-latest）` 在测试通过后会：

1. `dotnet publish`（win-x64，框架依赖）到临时目录并补齐 `engine/`、`models/` 占位与示例配置
2. 以 artifact `suiyi-portable-win-x64` 上传整个目录（Actions 会再打成 zip 供下载）

**不含**真实 `suiyi-engine.exe` 与模型权重。拿到 zip 后把引擎产物放进 `engine\` 即可本地试跑。
