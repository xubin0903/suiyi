# M2 实机测试

这份文档面向在自己的 Windows 电脑上验收 M2「复制即翻译」的人：从一台干净的 Windows 10/11 x64 开始，从源码跑起翻译服务和客户端，再按清单逐项勾选。熟悉的话大约 30 分钟能跑起来；模型下载时间取决于网络。

M2 还没有安装包，也没有模型按需下载（都在 M4），所以下面全部从源码运行。命令一律是 **Windows PowerShell**，在**仓库根目录**执行，除非另有说明。

相关文档：[引擎 README](../../engine/README.md)、[模型目录约定](../engine/模型目录约定.md)、[HTTP API](../engine/HTTP-API.md)、[性能基线](../engine/性能基线.md)、[客户端 README](../../client/README.md)。

## 1. 环境要求

| 项 | 要求 |
|----|------|
| 系统 | Windows 10 21H2 及以上，或 Windows 11，x64 |
| 参考机 | 4 核及以上 x64 CPU、8 GB 内存、SSD（与 [性能基线](../engine/性能基线.md) 的参考机一致） |
| 网络 | 转换模型时需要访问 Hugging Face 和 `object.pouta.csc.fi`；转换完成后翻译不需要联网 |
| 软件 | Python 3.11、.NET 8 SDK、Git（安装见下一节） |

**磁盘空间（估算）：**

| 内容 | 大小 | 依据 |
|------|------|------|
| mvp 五个模型转成 int8 之后（仓库根 `models/`） | 约 0.6 GB | [模型目录约定](../engine/模型目录约定.md)实测：`opus-mt-zh-en`、`opus-mt-en-zh` 各约 84 MB，`opus-mt-zho-jpn-tc-big-2022-07-28` 约 222 MB，`opus-mt-eng-jpn-2021-02-18` 约 86 MB；`opus-mt-ja-en` 未单独实测，按同规格约 84 MB 估 |
| Hugging Face 下载缓存（`%USERPROFILE%\.cache\huggingface`） | 约 0.9 GB | 三个 HF 模型的 `pytorch_model.bin`（`engine/model_manifest.json` 的 `weight_bytes`） |
| 日语模型原始 zip 缓存（`models\.cache\`） | 约 1.1 GB | 776 MB + 289 MB（[模型目录约定](../engine/模型目录约定.md)） |
| Python 虚拟环境（含转换用的 CPU 版 torch） | 未实测，按 1–2 GB 预留 | — |

合计建议至少预留 **5 GB**。转换完成后可以删掉两份缓存（见 §4），只留 `models/`。

## 2. 安装 Python、.NET、Git

可以用安装包，也可以用 `winget`。每装完一个，**新开一个 PowerShell 窗口**再验证（PATH 才会刷新）。

### Python 3.11

```powershell
winget install Python.Python.3.11
```

或到 python.org 下载 3.11 安装包，安装时勾选「py launcher」和「Add python.exe to PATH」。

验证：

```powershell
py -3.11 --version    # 预期：Python 3.11.x
python --version      # 预期：Python 3.11.x（若是别的版本，下面建 venv 时改用 py -3.11）
```

### .NET 8 SDK

```powershell
winget install Microsoft.DotNet.SDK.8
```

验证：

```powershell
dotnet --version      # 预期：8.0.x
```

### Git

```powershell
winget install Git.Git
```

验证：

```powershell
git --version         # 预期：git version 2.x
```

## 3. 获取源码与建虚拟环境

```powershell
git clone https://github.com/xubin0903/suiyi.git
cd suiyi
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -U pip
pip install -e "engine[dev]"
python -m suiyi_engine --version    # 预期：0.0.1
```

- 虚拟环境必须建在**仓库根目录**、名字叫 `.venv`：客户端会从自己的 exe 所在目录向上找仓库根，用 `.venv\Scripts\python.exe` 启动翻译服务（查找顺序见 [客户端 README](../../client/README.md#开发模式下的翻译服务)）。
- `"engine[dev]"` 的**引号不能省**，否则 PowerShell 会把方括号当成通配符。
- `Activate.ps1` 报「在此系统上禁止运行脚本」时，只对当前窗口放开：

  ```powershell
  Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
  .\.venv\Scripts\Activate.ps1
  ```

  或者长期放开当前用户：`Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned`。也可以不激活，直接用 `.venv\Scripts\python` 执行后面的命令。

## 4. 转换模型

先装转换依赖。CPU 版 torch 要先装，避免 pip 拉体积更大的默认版本（见 [模型目录约定](../engine/模型目录约定.md#安装转换依赖)）：

```powershell
pip install torch --index-url https://download.pytorch.org/whl/cpu
pip install -e "engine[convert]" --upgrade-strategy only-if-needed
```

转换正式清单 `engine/model_manifest.json` 里全部 mvp 模型（中↔英、中→日、英→日、日→英五个；日→中走英文中转，不需要单独的模型）：

```powershell
python scripts/convert_models.py --tier mvp
```

- 输出在仓库根 `models\<模型 id>\`。已经转换过、revision 和量化一致的模型会打印「已存在」并跳过；中途失败只删半成品，重跑即可继续。
- 耗时主要取决于下载速度（需要下载约 2 GB，见 §1）。本文没有 Windows 上的实测耗时，请在 §9 记录表里记下。
- **网络问题**：Hugging Face 下载由 `huggingface_hub` 完成，它遵循系统代理环境变量（`$env:HTTPS_PROXY = "http://<代理地址>:<端口>"`），也支持用 `$env:HF_ENDPOINT` 指向你自己信任的镜像。本文不推荐具体的第三方镜像。日语两个模型从 `object.pouta.csc.fi` 下载 zip 并校验 sha256，校验不过会失败、不留半成品。
- 转换结束后在仓库根执行 `git status`，不应出现模型文件（`/models/` 已被忽略）。

**转换完以后（可选）：**

- 转换依赖可以卸掉，只保留运行时依赖：`pip uninstall -y torch transformers huggingface_hub`。**不要**卸载 `ctranslate2` 和 `sentencepiece`，翻译服务运行时要用。
- 可以删除 `%USERPROFILE%\.cache\huggingface` 和 `models\.cache\` 两份下载缓存。以后要用 `--force` 重新转换时会重新下载。

## 5. 单独验证翻译服务

先不开客户端，确认服务本身能跑：

```powershell
python -m suiyi_engine serve --preload zh-en,en-zh
```

标准输出会打印监听地址（默认 `http://127.0.0.1:18780`）、模型目录、可用语向数量和解码参数。另开一个 PowerShell 窗口：

```powershell
Invoke-RestMethod http://127.0.0.1:18780/health
# 预期：status 为 ok，loaded_models 含 opus-mt-en-zh、opus-mt-zh-en

Invoke-RestMethod http://127.0.0.1:18780/languages

$payload = '{"text":"今天天气很好。","source":"auto","target":"en"}'
Invoke-RestMethod http://127.0.0.1:18780/translate -Method Post `
  -ContentType "application/json; charset=utf-8" `
  -Body ([System.Text.Encoding]::UTF8.GetBytes($payload))
# 预期：text 为英文译文，source 为 zh，route 为 opus-mt-zh-en
```

字段和错误码见 [HTTP API](../engine/HTTP-API.md)。`--preload` 缺模型时服务会非零退出，并提示缺失的模型 id。

验证完在服务窗口按 **Ctrl+C** 停掉。**测试客户端前务必停掉手动起的服务**：客户端发现端口上已有随译服务时会直接复用（`Ready(External)`），这时就测不到自己拉起、崩溃重启、退出清理这些行为（清单 A5 专门测复用）。

## 6. 构建与运行客户端

```powershell
dotnet build client/Suiyi.sln -c Release
dotnet run --project client/src/Suiyi.App -c Release
```

也可以直接双击构建出来的 `client\src\Suiyi.App\bin\Release\net8.0-windows\Suiyi.exe`（它同样会向上找到仓库根的 `.venv`）。

- 客户端没有主窗口，启动后常驻**任务栏右下角托盘**（可能在「显示隐藏的图标」里），右键菜单「退出」才结束。
- 客户端会自己拉起翻译服务（`.venv\Scripts\python.exe -m suiyi_engine serve --port 18780 --preload zh-en,en-zh`），不弹控制台窗口；客户端退出或被强杀时服务随之结束。
- 命令行参数 `-- --hotkey "Ctrl+Shift+Y"` 可临时换快捷键（不写回设置）；`-- --popup-demo` 轮播浮窗的各个状态；`-- --tray-demo` 轮换托盘图标状态。

## 7. 设置文件与日志

| 内容 | 位置 | 覆盖方式 |
|------|------|----------|
| 设置 | `%APPDATA%\suiyi\settings.json` | 环境变量 `SUIYI_CONFIG_DIR` 指定目录 |
| 客户端日志 | `%LOCALAPPDATA%\suiyi\logs\client-YYYYMMDD.log` | 环境变量 `SUIYI_LOG_DIR` 指定目录 |
| 翻译服务输出 | `%LOCALAPPDATA%\suiyi\logs\engine-YYYYMMDD.log` | 同上 |

- 托盘「打开设置文件」用记事本打开设置（文件不存在时先写出默认设置），「打开日志目录」打开日志文件夹。
- 日志按天滚动，保留 7 天，**不记录剪贴板正文和译文**，只记长度、耗时、语种和原因。
- 设置**不热重载**：手工改完要托盘「退出」再重新启动。托盘里的「暂停监听」「目标语言」会立即生效并写回文件。

常用改法（字段全表见 [客户端 README · 设置文件](../../client/README.md#设置文件)）：

| 想做的事 | 改哪里 |
|----------|--------|
| 默认目标语言改成英文 | `"primaryTarget": "en"`（也可以在托盘「目标语言」里切换） |
| 换快捷键 / 禁用快捷键 | `"hotkey": { "translate": "Ctrl+Shift+Y" }` / `""` |
| 浮窗 3 秒自动消失 / 不自动消失 | `"popup": { "autoHideSeconds": 3 }` / `0` |
| 换端口 | `"engine": { "port": 18790 }` |
| 模型不在仓库根 `models/` | `"engine": { "modelsDir": "D:\\suiyi-models" }`（JSON 里反斜杠要写两个） |
| 预加载更多语向 | `"engine": { "preload": "zh-en,en-zh,ja-en" }` |

## 8. M2 测试清单

**准备：** 按 §3–§6 跑起客户端，停掉手动起的服务；准备记事本和浏览器；打开日志目录备查。「结果」栏填 ✅ 通过 / ❌ 失败 / ➖ 未测，失败的在「备注」里写现象，并按 §11 反馈。

测试用句（可以换成你自己的，不要用隐私内容）：

- 英文：`The quick brown fox jumps over the lazy dog.`
- 中文：`今天天气很好，我们去公园散步吧。`
- 日文：`今日はとても良い天気ですね。`

## 9. 延迟记录表

### 怎么测端到端 P95（≤ 2000 ms）

端到端耗时 `e2e_ms` 从复制（系统通知剪贴板变化）或按下快捷键算起，到浮窗显示出译文为止。客户端每翻译完一次写一行日志（不含正文），例如：

```
翻译完成：trigger=Monitor chars=12 en→zh route=opus-mt-en-zh requests=1 e2e_ms=380 http_ms=210 server_ms=180；最近 10 次：P50 350 ms，P95 420 ms
```

1. 启动客户端，等托盘变蓝「就绪」（不要在「正在准备」时复制：等待服务的那次不计入统计）。
2. 在记事本或浏览器里，依次复制 **10 句不同的**中文或英文句子（每句 10–50 字，避免 2 秒内重复被过滤），每次等译文出来再复制下一句。
3. 读结果，任选一种：
   - 托盘「关于」里的「端到端延迟：最近 10 次：P50 … ms，P95 … ms」；
   - 日志最后一行「翻译完成」末尾的 P50 / P95；
   - 用 PowerShell 列出今天所有的 `e2e_ms`：

     ```powershell
     $log = "$env:LOCALAPPDATA\suiyi\logs\client-$(Get-Date -Format yyyyMMdd).log"
     Select-String -Path $log -Pattern 'e2e_ms=(\d+)' | ForEach-Object { $_.Matches[0].Groups[1].Value }
     ```

统计只保留最近 20 次，退出客户端后清零。P95 用最近秩法（10 次时就是第 10 大，即最大值）。

### 冷启动与内存

- **冷启动到就绪**：客户端日志里 `翻译服务状态：Ready(Managed)：翻译服务已就绪（pid …，用时 N ms）` 的 N，是从拉起服务到服务可以翻译的时间。最好在电脑重启后第一次启动时测一次（磁盘冷读），再在之后测一次。
- **服务内存**：任务管理器 →「详细信息」→ 右键列标题 →「选择列」→ 勾选「工作集(内存)」，看 python.exe（venv 可能有两个，取占用大的那个）。就绪后先各翻一句中→英、英→中再读。

## 10. 常见问题

| 现象 | 原因与处理 |
|------|-----------|
| 托盘提示「未找到 suiyi_engine：请在仓库根目录创建 .venv 并执行 pip install -e engine」，或手动运行报 `No module named suiyi_engine` | `.venv` 不在仓库根、名字不对，或没装引擎。按 §3 在仓库根重建 `.venv` 并 `pip install -e "engine[dev]"` |
| 「未找到 Python：…」/「无法启动 Python：…」 | 客户端没找到 `.venv\Scripts\python.exe`，也没有 `py -3.11` 或 PATH 上的 `python`。检查 §3；或在设置里写 `engine.pythonPath` 指向解释器完整路径 |
| 「端口 18780 被其他程序占用，请在设置中修改 engine.port」 | 端口上跑着别的程序。`netstat -ano \| findstr 18780` 找到 PID 后关掉，或改 `engine.port` |
| 「缺少模型：opus-mt-xx-yy，请按 docs/engine/模型目录约定.md 转换」 | `engine.preload` 里的语向没有转换模型。按 §4 转换，或检查 `engine.modelsDir` 是否指向模型目录 |
| 「启动超时：翻译服务 30 秒内未就绪，已结束进程」 | 冷盘读模型慢、杀毒软件扫描或机器负载高。看 `engine-*.log`；稍后点浮窗「重试」或托盘「重启翻译服务」 |
| 复制后没反应，日志里也没有「剪贴板」相关行 | 可能被杀毒或安全软件拦截了剪贴板监听；或托盘处于「已暂停监听」。把仓库目录或 `Suiyi.exe` 加入杀毒软件信任列表后重试 |
| 快捷键按了没反应，或只翻译了旧的剪贴板 | 杀毒软件可能拦截模拟按键（`SendInput`）；目标窗口以管理员身份运行时系统也会拦截（清单 D8），此时会退化为翻译当前剪贴板 |
| 双击 `Suiyi.exe` 弹出 SmartScreen「Windows 已保护你的电脑」 | 本机构建的 exe 没有签名。点「更多信息」→「仍要运行」，或改用 `dotnet run` 启动 |
| 译成日文的质量明显较差 | 已知问题，日语模型的选择与评测见 #25 和 [评测](../engine/评测.md)。反馈时请给出不含隐私的例句 |

更多服务端失败提示见 [客户端 README · 开发模式下的翻译服务](../../client/README.md#开发模式下的翻译服务)。

## 11. 问题反馈

在 GitHub 上用 **[问题反馈（Bug）模板](https://github.com/xubin0903/suiyi/issues/new?template=bug.yml)** 开 Issue（模板文件是仓库里的 `.github/ISSUE_TEMPLATE/bug.yml`）。请附上：

1. **版本或 commit**：仓库根 `git rev-parse --short HEAD` 的输出。
2. **系统与环境**：Windows 版本、CPU / 内存、显示缩放、Python 版本。
3. **复现步骤**：对应本清单的编号（如「F3」）和具体操作。
4. **期望与实际**：浮窗或托盘提示的原文字，必要时附截图（遮住原文和译文）。
5. **日志**：`%LOCALAPPDATA%\suiyi\logs\` 下出问题当天的 `client-YYYYMMDD.log` 和 `engine-YYYYMMDD.log`（设置了 `SUIYI_LOG_DIR` 时在该目录；托盘「打开日志目录」可直接打开）。日志不含剪贴板正文，可以直接附；也可以只贴出问题前后的几十行。
6. **设置**：改过设置的话，附 `%APPDATA%\suiyi\settings.json`。

**请不要贴你复制或翻译过的原文、译文、密码等隐私内容。** 需要例句时换成不含隐私的句子。
