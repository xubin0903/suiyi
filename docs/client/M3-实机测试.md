# M3 实机测试

这份文档面向在 Windows 上验收 M3「框选翻译」的人。**前提是已经按 [M2 实机测试](M2-实机测试.md) 在 `E:\suiyi` 装好并跑通过 M2**（Python 3.11 + `.venv`、.NET 8 SDK、翻译模型都在）。这里只写从 M2 升级到 M3 的增量步骤和 M3 的测试清单，不重复全新安装；环境要求、翻译模型转换、M2 清单都见 M2 文档。熟悉 M2 环境的话，升级大约 15 分钟（主要是下载 OCR 依赖和模型）。

命令一律是 **Windows PowerShell**，在 **`E:\suiyi`（仓库根）** 执行，除非另有说明。

相关文档：[OCR 选型与许可证](../engine/OCR选型与许可证.md)（模型、下载脚本、离线）、[OCR 核心](../engine/OCR核心.md)、[HTTP API](../engine/HTTP-API.md)、[客户端 README · 框选翻译](../../client/README.md#框选翻译)、[客户端 README · 框选截屏](../../client/README.md#框选截屏)。

## 1. 从 M2 升级

### 1.1 更新源码

先右键托盘「退出」随译（运行中的 `Suiyi.exe` 会锁住构建输出）。

```powershell
cd E:\suiyi
git status                 # 预期：没有本地改动；有的话先自行处理
git checkout main
git pull
git log --oneline -1       # 记下 commit，填 §7 记录表
```

### 1.2 安装 OCR 依赖

```powershell
.\.venv\Scripts\Activate.ps1
pip install -e "engine[ocr]"
python scripts\download_ocr_models.py audit
```

- `ocr` 组是 `rapidocr` + `onnxruntime`（带入 numpy、opencv、Pillow），**不含 torch / paddle / transformers**。版本范围见 `engine/pyproject.toml`。
- M2 装过的 `engine[dev]` 不受影响，这里只是在同一个 `.venv` 里补装 `ocr` 组。
- 体积：Windows CI 干净 venv 装 `engine[ocr]` 是 40 个包、约 376 MB（[OCR 选型与许可证](../engine/OCR选型与许可证.md)）。M2 的 `.venv` 已有 ctranslate2、numpy 等，实际新增会少一些。
- `audit` 预期最后一行为「未发现 torch / paddlepaddle / paddleocr / transformers」。M2 转换模型时装过 torch、后来没卸的话这里会报出来并返回非零：这只说明当前 venv 里有 torch，不影响运行；想让它通过可以按 M2 §4 卸掉转换依赖。
- `Activate.ps1` 被禁止运行时见 M2 §3。

### 1.3 下载 OCR 模型（PP-OCRv6 small）

```powershell
python scripts\download_ocr_models.py download
python scripts\download_ocr_models.py check
```

- 下载推荐组合的三个 ONNX：`PP-OCRv6_det_small`（9.9 MB）、`PP-OCRv6_rec_small`（21.2 MB）、`ch_ppocr_mobile_v2.0_cls_mobile`（0.6 MB，RapidOCR 要求存在，实际不启用），合计约 **31.7 MB**，来源为 `www.modelscope.cn`（清单 `engine/ocr_model_manifest.json`）。开发机实测约 12 秒。
- 写到 `<models_dir>\ocr\`，默认就是 `E:\suiyi\models\ocr\`（与翻译模型同一个 `models`）。**如果 M2 时把模型放在别处**（设置里配了 `engine.modelsDir`；设了 `SUIYI_MODELS_DIR` 环境变量的话脚本会自动跟随，不用加参数），两条命令都要加 `--models-dir <同一个目录>`，而且要写在子命令**前面**：`python scripts\download_ocr_models.py --models-dir D:\models download`（写在后面会报 unrecognized arguments）。
- `download` 是默认子命令（不写也一样），这里写全是为了和服务端、浮窗提示里的命令一致。每个文件校验字节数和 sha256，对不上会删掉并失败，重跑即可；已存在且校验通过的文件跳过，损坏的文件会重新下载。`check` 预期三行都是「正常」，只读本地，不联网。
- 网络需要代理时，下载使用 Python 标准库 `urllib`，遵循 `$env:HTTPS_PROXY`（推测，未在 Windows 实测）。

### 1.4 离线验证 OCR（不经过服务）

断开网络（关 Wi‑Fi 或拔网线）后：

```powershell
python scripts\download_ocr_models.py smoke engine\tests\fixtures\ocr\zh_web_01.png
python scripts\download_ocr_models.py smoke engine\tests\fixtures\ocr\ja_web_01.png
```

预期：打印模型目录、三个模型文件名、「加载 N ms，识别 N ms，N 行」和识别出的文字（样例图的正文见同名 `.txt`）。`smoke` 自己也会在进程内禁止网络连接，识别过程没有任何联网。记下加载和识别耗时填 §7。测完恢复网络。

### 1.5 重新构建并启动客户端

```powershell
dotnet build client/Suiyi.sln -c Release
dotnet run --project client/src/Suiyi.App -c Release
```

预期：构建 0 错误；托盘先橙后蓝（就绪）。右键托盘，「翻译剪贴板」下面多了一项「框选翻译（Ctrl+Alt+S）」。

- 客户端拉起服务时默认带 `--preload-ocr`（设置 `engine.preloadOcr`，默认开启）：`engine-YYYYMMDD.log` 里有「OCR 已预热 N ms」，之后第一次框选不用再等 OCR 加载。预热会让「就绪」晚一点（开发机约 0.6 s），见清单 O8。
- 缺 OCR 模型或依赖时服务**照常启动**、复制翻译不受影响：engine 日志有一行「警告：--preload-ocr 未能加载 OCR，文本翻译照常可用，框选翻译将返回 503：…」，客户端日志有「框选翻译：OCR 不可用 reason=… missing=…」，框选时浮窗提示怎么修（清单 O3–O5）。

## 2. 单独验证服务的 OCR 接口

接口定义见 [HTTP API](../engine/HTTP-API.md)（请求体是原始 PNG，`Content-Type: image/png`）。先退出客户端，再手动起服务：

```powershell
python -m suiyi_engine serve --preload zh-en,en-zh --preload-ocr
```

预期启动输出里有「OCR 已预热 N ms」；缺 OCR 模型时改为一行「警告：--preload-ocr 未能加载 OCR…请执行 python scripts/download_ocr_models.py download 下载 OCR 模型」，服务照常启动。另开一个窗口：

```powershell
Invoke-RestMethod http://127.0.0.1:18780/health
# 预期：ocr_loaded 为 True，ocr_error 为空；缺模型时 ocr_loaded 为 False，ocr_error 里 reason 为 models_missing、missing_models 列出缺的模型

Invoke-RestMethod 'http://127.0.0.1:18780/ocr?lang=auto' -Method Post `
  -InFile engine\tests\fixtures\ocr\zh_web_01.png -ContentType image/png
# 预期：paragraphs、text 与 zh_web_01.txt 一致或接近，image 为图片尺寸

Invoke-RestMethod 'http://127.0.0.1:18780/ocr_translate?source=auto&target=en&fallback_target=zh' -Method Post `
  -InFile engine\tests\fixtures\ocr\zh_web_01.png -ContentType image/png
# 预期：translation.results 与 paragraphs 一一对应，为英文译文；elapsed_ms 含 ocr / translate / total
```

缺模型时后两条返回 503，PowerShell 报错信息里是 `ocr_unavailable` 的 JSON（`details.reason`、`details.missing_models`）。补齐模型后**不用重启服务**，下一次请求就能用。测完 Ctrl+C 停掉服务再测客户端（原因同 M2 §5）。

## 3. 设置项与命令行

设置文件、日志位置同 M2 §7。M3 相关字段（全表见 [客户端 README · 设置文件](../../client/README.md#设置文件)）：

| 字段 | 默认 | 说明 |
|------|------|------|
| `hotkey.region` | `"Ctrl+Alt+S"` | 框选翻译快捷键，`""` 禁用。格式非法回落默认值并写 Warning；与 `hotkey.translate` 相同时框选快捷键被禁用，托盘提示一次 |
| `engine.preloadOcr` | `true` | 启动时预热 OCR 模型（追加 `--preload-ocr`）。缺模型时只告警、照常启动。关掉可省内存，代价是首次框选多等一次 OCR 加载。环境变量 `SUIYI_ENGINE_PRELOAD_OCR=1/0` 可覆盖 |

命令行（加在 `dotnet run ... -c Release --` 后面，不写回设置）：

| 参数 | 作用 |
|------|------|
| `--region-demo` | 框选完成后另存 PNG 到 `%TEMP%\suiyi-region-demo\region-<时间>-<宽>x<高>.png`，托盘气泡显示路径。**PNG 是屏幕内容，测完请删除，不要上传含隐私的截图** |
| `--region-hotkey "Ctrl+Shift+F2"` | 临时换框选快捷键 |
| `--popup-demo` | 每 3 秒切换一个浮窗状态（后半段是框选翻译的各状态） |

框选相关日志（`%LOCALAPPDATA%\suiyi\logs\client-YYYYMMDD.log`，不含图片和识别出的文字）：

| 日志 | 含义 |
|------|------|
| `框选：完成 W×H 物理像素，位置 …，显示器 …（缩放 N%），PNG N 字节，耗时 N ms` | 一次框选成功 |
| `框选：已取消` / `框选：遮罩已显示，忽略重复触发` / `框选：截屏失败` | 取消、重复触发、截屏异常 |
| `框选翻译完成：trigger=… size=… bytes=… paragraphs=… untranslated=… ocr_e2e_ms=… http_ms=… server_ocr_ms=… server_translate_ms=…；框选最近 N 次：P50 … ms，P95 … ms` | 一次框选翻译显示完成（另有一行服务调用层的 `框选翻译完成：size=… client=…ms`） |
| `框选翻译失败：… kind=… code=… status=… precheck=…` | 识别或翻译失败；`precheck=True` 表示客户端预检拦下、没有发请求 |
| `框选翻译：OCR 不可用 reason=… missing=…，框选时浮窗会提示下载命令` | 服务就绪时 `/health.ocr_error` 非空（缺 OCR 模型或依赖） |
| `翻译：en→zh 的模型可能已被空闲卸载（model_idle_unload_s=600；opus-mt-…=冷(612s)），按冷启动超时 10000 ms（原 1500 ms）` | #94：该方向的模型距上次使用已接近 `model_idle_unload_s`（或本次运行还没用过，显示「冷(首次)」），这次按冷启动超时等待。框选翻译为 `框选翻译：… 按冷启动超时 30000 ms（原 15000 ms）` |
| `翻译：/translate en→zh 1500 ms 超时，按冷启动超时 10000 ms 自动重试一次` | #94：第一次超时，自动重发一次（框选为 `/ocr_translate … 15000 ms 超时，按冷启动超时 30000 ms 自动重试一次`）；重试也超时才在浮窗报「翻译超时」 |

## 4. 测试准备

- 按 §1 升级并启动客户端；停掉手动起的服务。
- 准备测试素材（**不要用含隐私的内容**）：
  - 仓库自带的 OCR 样例图 `engine\tests\fixtures\ocr\`：`zh_web_01.png`（中文网页）、`en_doc_01.png`（英文文档）、`ja_web_01.png`（日文横排）、`ja_vertical_01.png` / `ja_vertical_03.png`（日文竖排），用「照片」或「画图」以 100% 打开；
  - 浏览器里打开的公开网页（维基百科中/英/日文条目等）。
- 「结果」栏填 ✅ 通过 / ❌ 失败 / ➖ 未测。失败的在「备注」里写现象，按「失败时收集」一栏准备材料，按 §9 提 Issue。
- 「失败时收集」里的**日志**指 `client-YYYYMMDD.log` 中对应时间的几十行（需要时加上 `engine-YYYYMMDD.log`）；**截图**用 Win+Shift+S 截全屏或相关区域，**遮住原文和译文**。

### 5.3 O · 引擎 OCR 客户端（#66）：预检、超时、上传

**准备噪声图**（用于制造超大 PNG；随机噪声几乎不能压缩，字节数可控）。在已激活 `.venv` 的窗口执行（numpy、Pillow 由 `engine[ocr]` 装入）：

```powershell
python -c "import numpy as np, os; from PIL import Image; rng = np.random.default_rng(0); [Image.fromarray(rng.integers(0, 256, (h, w, 3), dtype=np.uint8)).save(n) or print(n, os.path.getsize(n)) for n, w, h in [('noise-4k.png', 3840, 2160), ('under-8mib.png', 1660, 1660), ('over-8mib.png', 1700, 1700)]]"
```

### 5.9 I · 空闲卸载后的冷启动（#94，依赖引擎 #93）

引擎 #93 起，翻译模型空闲 `model_idle_unload_s` 秒（默认 600）会被卸载，下次用到时重新加载（多 0.2–0.4 s，慢盘更久）。客户端 #94：某个方向距上次成功翻译接近这个时长（提前 30 秒）或本次运行还没用过时，按冷启动超时（复制翻译 10000 ms、框选 30000 ms）等待；任何一次超时都先自动重试一次（冷启动超时），仍失败才提示。设计见 [客户端 README · 超时](../../client/README.md#超时timeoutpolicy纯函数)。

**缩短等待（I3–I6 用）：** 在启动随译的同一个 PowerShell 里先设 `$env:SUIYI_MODEL_IDLE_UNLOAD = "60"`，再 `dotnet run --project client/src/Suiyi.App -c Release`（服务进程继承这个环境变量；测完关掉这个窗口或 `Remove-Item Env:SUIYI_MODEL_IDLE_UNLOAD` 后重启随译）。60 秒时客户端判冷的阈值是 30 秒。

**模拟服务卡顿（I6、I7 用）：** 「资源监视器」（`resmon`）→「CPU」页 → 在「进程」列表里右键 `python.exe`（取内存大的那个）→「挂起进程」，恢复时右键 →「恢复进程」。**挂起不要超过 20 秒**，否则看门狗会判服务无响应并重启它。

## 6. 延迟记录方法

`ocr_e2e_ms` 从**松开鼠标、截图编码完成**算起（拖拽选区的时间不算），到浮窗显示出结果、完成布局为止。

1. 启动客户端，等托盘变蓝；先框选一次让 OCR 模型加载（这次算冷加载，填到记录表的冷加载栏）。
2. 在浏览器或 `zh_web_01.png` 上，连续框选 **10 次** ≤ 1280×720 的段落区域（例如一段 5–10 行的正文），每次等结果出来再框下一次。等待过服务就绪的那次不计入统计。
3. 读结果，任选一种：
   - 托盘「关于」里的「框选翻译延迟：最近 10 次：P50 … ms，P95 … ms」；
   - 日志最后一行 `框选翻译完成：… ocr_e2e_ms=…` 末尾的 P50 / P95；
   - 用 PowerShell 列出今天所有的 `ocr_e2e_ms` 和服务端分段耗时：

     ```powershell
     $log = "$env:LOCALAPPDATA\suiyi\logs\client-$(Get-Date -Format yyyyMMdd).log"
     Select-String -Path $log -Pattern 'ocr_e2e_ms=(\d+).*server_ocr_ms=(\d+) server_translate_ms=(\d+)' |
       ForEach-Object { $g = $_.Matches[0].Groups; "$($g[1].Value) $($g[2].Value) $($g[3].Value)" }
     ```

统计只保留最近 20 次，退出客户端后清零，与复制翻译的统计分开。P95 取法同 M2 §9（10 次时为最大值）。

**服务内存：** 任务管理器「详细信息」里 python.exe 的「工作集(内存)」（取大的那个）。先在托盘就绪、还没框选时读一次，再在框选过一次（OCR 已加载）后读一次，两者之差就是 OCR 加载的增量（测这项时先按 O7 关掉 `preloadOcr`）。再在默认开启预热时，读一次刚就绪、还没框选时的内存，应接近前面「OCR 已加载」的值。

## 8. 常见问题

| 现象 | 原因与处理 |
|------|-----------|
| 框选后浮窗「翻译服务返回了无法识别的响应」 | 服务是旧版本、没有 OCR 接口：确认 `git pull` 到最新，并托盘「退出」后重新启动随译（服务会随之重启）。之前手动起的旧服务还在运行时客户端会直接复用它，先把它关掉 |
| 浮窗「OCR 模型未安装：…」或「OCR 模型文件不完整或已损坏」 | `<models_dir>\ocr\` 缺文件或校验不过。照浮窗第二行在仓库根执行 `python scripts\download_ocr_models.py download`，完成后点「重试」（不用重启）；`check` 可以看哪个缺失。模型不在仓库根 `models` 时要在子命令前加 `--models-dir <目录>`（见 §1.3） |
| 浮窗「OCR 组件未安装」 | `.venv` 里没装 `engine[ocr]`。按浮窗提示在仓库根执行 `pip install -e "engine[ocr]"`，然后托盘「重启翻译服务」 |
| `smoke` 或服务日志报 `DLL load failed while importing onnxruntime_pybind11_state` | onnxruntime 需要 Microsoft Visual C++ 2015–2022 可再发行组件（x64）。从微软官网安装 `vc_redist.x64.exe`（`https://aka.ms/vs/17/release/vc_redist.x64.exe`）后重开 PowerShell 重试（推测，未在 Windows 实测） |
| `pip install -e "engine[dev,ocr]"` 很慢或失败 | opencv-python、numpy、onnxruntime 较大（见 §1.2）。需要代理时设置 `$env:HTTPS_PROXY`；Python 必须是 3.11（M2 的 `.venv`），numpy 2.5 起要求 3.12 |
| 截图是黑色、识别为空 | 受保护内容（DRM 视频）、部分独占全屏程序、部分远程桌面窗口不允许截屏，属系统限制（清单 Q6）。换窗口化模式再试 |
| 按 `Ctrl+Alt+S` 没有遮罩，日志「框选：截屏失败」，托盘「框选截屏失败，请重试（详情见日志）」 | 可能被杀毒或安全软件拦截了截屏。把 `E:\suiyi` 或 `Suiyi.exe` 加入信任列表后重试，并附日志反馈 |
| 按 `Ctrl+Alt+S` 完全没反应 | 快捷键被占用（启动时托盘有提示，见 P10）或与翻译快捷键相同被禁用（P8）。改 `hotkey.region` 后重启；也可以用托盘「框选翻译」 |
| 框选的内容和看到的不一致（偏移、缩放不对） | 多显示器 / 混合缩放问题。附日志里「框选：完成」一行、「显示设置」截图和 `--region-demo` 的 PNG（确认无隐私）反馈 |
